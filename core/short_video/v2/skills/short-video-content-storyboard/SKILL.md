# 短视频内容分镜 Skill

目标：让每个片段容易生成，前后能够剪接，最终组成少于60秒、无需前情即可理解的完整短视频。内容风格继承素材与用户要求，趣味、悬疑或爽感不是强制结构。

输入为当前视频文案、创作配置与资产目录；本阶段只输出宿主要求的分镜 JSON，不生成媒体或改写上游文件。

仅在用户从原文页明确选择本 Skill 时启用，不由 Agent 自动选择；未选择时不加载本文件。

## 1. 按单次生成能力拆镜

- 默认一条分镜对应一个独立生成片段，内部保持连续画面；需要硬切、换地点、换观察位置或进入新的动作阶段时拆镜，不把多个切镜藏在同一条里。
- 一镜围绕一个主要动作或少量自然连续的小动作。写清“起始状态 → 动作过程 → 结束状态”，不把起身、奔跑、抢物、打斗和长对白同时塞进一镜。
- 减少多人同时运动、复杂肢体接触、连续大幅位移与多件道具同时变化；必要互动按明确动作节点拆开，不能只缩短时间数字。
- 一个镜头安排一个主要运镜，说明方向及起止构图；固定镜头可优先用于表演和复杂动作，不堆叠推拉、环绕、甩镜。
- `action` 写可观察动作，`visual_prompt_draft` 描述同一镜的主体、环境、构图与连续运动，不用抽象情绪或无关画质词代替实际内容。

## 2. 分别安排单镜时长和全片时长

- 常规单镜优先5–8秒，依据动作完成、信息辨识、声音和停顿决定具体时长；不默认每镜相同，也不平均分配总时长。
- 物件插入、短反应、动作衔接或快切确有需要时允许低于5秒，不为凑下限拖长。超过8秒先考虑拆镜；仅在连续表演无法合理拆开、且任务明确允许时保留，并在现有 `duration_exception_reason` 写明内容依据。
- 官方模型卡列出 H3 输出范围为4–15秒，5–8秒是本项目的制作策略，不是官方最佳时长结论。`duration_ms` 表示分镜计划采用的时长；低于实际工作流支持范围时需后续按可用长度生成并裁切，不能声称工作流已支持该短时长或已自动裁切。也不能把实际文件时长当成必然精确等于计划时长。
- 总时长满足 `0 < Σduration_ms < 60000`。`target_duration_ms` 在1–59999之间时，逐镜总和与其一致；未指定时自然结束，不凑满一分钟。目标大于等于60000时报告范围冲突，不静默更改配置。
- 项目旧的 `shot_duration_range_ms` 仅供参考，本任务按上述5–8秒及短镜例外设计。动作来不及完成时拆解动作；内容整体装不下时指出需压缩的上游视频块，不用假时长或高速口播制造达标。
- 声音先按实际发声文字估算，中文清晰表达可从每秒3–4字起估，再考虑换人、停顿和情绪。顺序发生的声音与动作累计时间，并行发生的按覆盖它们的较长时间安排，不能一律相加或一律并行。
- 长旁白、画外对白可以跨镜连续，按实际发声顺序分配文字，不在每镜重复整段。音乐与环境声通常不额外占时；必须等待的反应和静默需要计时。

## 3. 为下一镜留下可接的状态

- 保持人物位置、朝向、视线、服装、光线和道具持有状态。前镜动作结束与后镜开始应能衔接；换视角仍要让观众理解空间，不靠模型自行补出中间动作。
- 参考图用于固定已知外观、场景和物件。只有输入确实提供首帧或尾帧时，才按图描述连续运动路径；外观参考图不自动等于首帧，不虚构图片编号或首尾帧绑定。
- 每镜画面描述包含本镜必要信息，不仅写“同上”。内容在本条内表达清楚并给出结果或落点，不为套笑点、反转或下集悬念新增剧情。

## 4. 输出与检查

- 沿用宿主 JSON 字段、真实资产与状态ID、`video_block_refs` 和准确 `source_refs`；保留全部上游视频块的真实内容与核心因果，不能虚挂引用。时长用正整数毫秒，绝对时间由程序累加。
- `characters` 只列画面中可见人物；画外对白设 `voice_over=true`，仅声音角色不入画。没有对白用空列表，不强迫所有旁白变成口型对白。
- 检查四件事：单镜动作和运镜是否可执行；5–8秒或短镜例外是否与内容匹配；全片总时长与声音容量是否合理；前后状态和引用是否连续。相同时长、短于5秒本身不算错误，不通过随机改数字消除提示。
- 问题沿用 `issues` 契约，`severity="warning"`，定位具体 `shots` 字段，写明内容冲突和拆镜、重新分配声音或调整时长的办法。超时、明显声音超载和无法剪接不能判为通过；上游缺少结果或内容过长时如实反馈，不虚构剧情、不假称系统会自动回退。
- 按原始任务、最新候选和反馈修订，返回完整分镜；保留其他有效设计，重新核对总时长和衔接。文本审阅不等于已验证实际视频质量或配音时长。
