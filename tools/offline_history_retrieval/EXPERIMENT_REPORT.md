**结论。** 保留「最近 3 轮」作为当前对照，保留明确 ID 直取。词组匹配在模拟历史里找回了一部分早期改稿，可以保留为下一轮的对照分支。两种关键词方案都未达到首轮晋级条件，暂缓替换现有策略。二字匹配在模拟语料的前 3 名未增加命中，在真实语料中比纯词组少保留 1 个命中，因此本轮不选用。

## 实测

分母为各组题数。正例每题只有一个必需证据，表中的命中按实际入预算计算；这组数据的 Hit@3 与 Recall@3 相同。无证据题单列，任何非空结果记为误召回。

|---|---|---:|---:|---:|---:|---:|

模拟组继续晋级的条件是比 B0 至少净增 3 题，保留近处组 10 个命中，5 条无证据题返回空，以及明确 ID 的回归检查通过。两种关键词方案都符合 ID 回归检查，但各自新增 4 题并丢失 6 题，净少 2 题，缺证据题仍有误召回。整个实验各组均未返回截止时点之后的轮次。单次测量的耗时只记录为当前本机排序开销，样本量不足以据此判断实际运行性能。

## 下一轮目标

优先从 **B0 的真实组运行条件**派生一个打包实验分支，固定排名、查询、前 3 和 6,000 字符。唯一改变的是将过长整轮替换为带原消息 ID、镜号与字段的改稿证据，保留原文中解释改动缘由所必需的段落。记录每题压缩前后的证据和长度，核对目标字段是否仍保有原值或新值所需要的语义。

- **假设。** 只改证据打包，可以恢复排名已正确的两条长改稿。
- **晋级指标。** 恢复 `real-near-01` 与 `real-near-03`，真实近处组从 6/8 到 8/8，其他已有命中和来源 ID 均保留；所有上下文仍在预算内，逐项人工核对改稿值与原文一致。回查结果也记录，但这个实验的单一变量是打包。
- **排序后续。** 打包复核完成后，以纯词组为对照，单独试「按已应用或已改稿的状态筛候选」。先复核 `late-06`、`missing-03/05` 和真实会话中的开门多个版本，再用另一份真实会话或标为模拟的新故事复核。加入模型生成前，明确区分无证据澄清和允许的历史建议检索。

### 在 PyCharm 复跑

打开对应工作树，运行 [run_experiment.py](run_experiment.py) 即可复跑模拟语料。真实组在同一个运行配置里将 `--history` 指向实验工作树下的本地 `temp/rag-real-holdout/history.json`，将 `--queries` 指向该分支的 [real_queries.jsonl](real_queries.jsonl)。另用 `--output` 指向新文件可以把新跑结果与已提交的结果并排看。

真实快照在本机，来源是实验时当前 NovelWriter 项目的分镜会话。复建时保留同一用户消息与 AI 回复完整配对的轮次，按时间顺序编号 `T1` 至 `T27`，每轮用户和回复分别记为 `r1u`、`r1a` 等。先核对快照指纹；原会话后来增长时，把它当成新语料版本登记。
