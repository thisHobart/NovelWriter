# 分镜长对话 RAG 实验手册

这份手册用于为后续目标选择数据、设计对照实验、制定完成指标，并根据结果决定下一步。实验基线由语料版本、对照方法、查询、历史可见范围和实测结果共同定义。当前用 27 轮真实分镜对话和首份 50 轮模拟语料做对照。模拟语料含 10 个阿澈分镜修改案例与 10 条模拟应用记录。下文先给纯检索实验方案，并保留已有基线和通过离线验收的本地模型结果，首轮逐题差异见 [分镜历史检索实验报告](EXPERIMENT_REPORT.md)。

关联文件见 [模拟历史](history.json) · [检索模块](history_retrieval.py) · [PyCharm 演示入口](demo_history_retrieval.py)。


## 纯检索实验结论

**采用镜号、字段和应用状态过滤，加权关键词排序，以及字段证据校验。** 先按会话、截止轮次和明确条件筛选。普通连续追问沿用最近 3 轮，明确消息 ID 直取。旧改稿检索统一少量分镜词的写法，按 2–4 字片段覆盖率排序。程序核对命中词是否出现在候选的内容或对应字段中，明确「改成什么」时还核对新值。组装时保留原始消息、状态和已命中的字段，最多带 3 个来源轮，共 6,000 字符。无可信匹配时留空，已应用必须有程序回执。

## 纯检索实验方案

目标是在当前分镜会话里，用程序找回用户所指的旧改稿或应用回执。假设是**按镜号、字段和状态缩小候选，再用现有词组排序，可以提高旧改稿命中并减少错版本**。检索、排序、证据核对和打包都用本地程序完成。首轮限定为文本扫描和规则匹配，评估到历史证据装入 Prompt 为止。

### 方案怎么查

1. **准备证据。** 从已有 `revised_shots` 提取 AI 返回的改稿值，从程序的 `applied_diff` 提取已应用的旧值与新值。每条证据保留会话 ID、轮次、消息 ID、镜号、字段、值和状态。把已有的 `shot_id`／「镜号」、`action`／「动作」等字段名归一。状态「已应用」必须有可定位的程序回执。
2. **按当前问题筛选。** 程序在当前会话和检索截止轮次内查找。明确提及消息 ID 时直取。旧改稿问题里的「第 5 镜」「第 2 至第 9 镜」「动作」「最后应用」等可提取为条件。只有用户说「本镜」且页面已明确选镜时，才用页面镜号。指定多镜时核对同一份改稿是否覆盖相应镜头，以及每个明确字段是否属于对应镜头。
3. **排序与返回。** 有动作、物品等内容词时，先沿用已有的连续词组打分。条件足以直接定位时，例如「第 5 镜最后应用的动作是什么」，按回执顺序取截止位置之前最近一次同镜号、同字段的变更。找不到符合明确条件的记录时返回空。范围或版本有歧义时可以请用户补充；连续追问仍走最近 3 轮。
4. **打包证据。** 搜索可以细到镜号和字段，输出仍按来源轮次去重，沿用现有紧凑打包。历史证据最多 3 个来源轮，合计不超过 6,000 字符，保留原消息 ID、状态和命中的字段值。

例如问「第 5 镜最后应用的动作是什么」。可见记录里有一份第 5 镜的 AI 改稿和一条第 5 镜动作的程序回执时，以这条动作回执为证据。若唯一回执出现在查询截止轮次之后，当前查询返回空。

### 数据和对照怎么设

- **真实对话。** 复用本地 27 轮快照。`real_queries.jsonl` 有 8 道近处题、8 道旧改稿回查题和 3 道缺证据题。`real_validation_queries.jsonl` 有 8 道同会话改写题和 3 道缺证据题，已用于早期对照，可用作回归。真实快照能核实 AI 返回的改稿，应用正例需要有真实回执才能入组。
- **模拟回归。** 复用 50 轮语料及 `queries.jsonl` 的 10 道近处题、10 道回查题和 5 道缺证据题。已有语料含 10 条应用回执。按实验需要补上同词错镜、同镜错字段、草稿未应用、先后两版曾应用等易错场景。后续根据失败类型决定题目和轮次，记录真实与模拟来源。
- **冻结留出题。** 优先再取一个真实分镜会话，另标至少 8 道可回查题和 4 道缺证据题。如果只有当前真实会话，另写同等数量的新问题，结论限定于当前会话。按会话或改稿事件划分数据。对同一改稿的近处与远处问法留在同一组。每题标注可见截止轮、期望消息 ID、必要镜号及字段、状态，以及应返回证据、返回空或澄清。标签只用于评分。基准设计借用 LongMemEval 的时点推理、信息更新和缺证据时的行为分类。 [LongMemEval 论文](https://arxiv.org/abs/2410.10813)

| 对照与候选 | 用什么查 | 已记录的真实证据命中与误召回 |
|---|---|---|
| B0 最近历史 | 最近 3 轮和紧凑打包 | 近处 8/8，旧改稿 1/8，新问法 1/8，缺证据误召回 6/6 |
| B1 明确引用 | 用户提供消息 ID，由程序定位 | 真实 8/8，模拟 10/10 |
| B2 词组基线 | 只在改稿记录中匹配现有连续词组 | 近处 4/8，旧改稿 2/8，新问法 2/8，缺证据误召回 6/6 |
| C1 结构化过滤 + 词组排序 | 从 B2 增加镜号、字段和状态约束，已有词组评分与打包沿用 | 待测 |

B1 只衡量明确引用路径。自然语言效果用 B0、B2 和 C1 对照。上表是历史实测，正式对照需在同一批题上复跑并检查新增的镜号、字段和状态标签。

1. 在现有 `NovelWriter-offline-retrieval` 项目中用 Git 切分支。B0 结果见 `c6f7532`，从 B2 的结果提交 `26d4298` 创建 C1 分支，例如 `codex/rag-structured-keyword`。复用同一个项目目录和本地语料。
2. 冻结语料指纹、查询、每题的截止轮、同一会话范围、词组评分、最多 3 个来源轮和 6,000 字符。实现候选后，在 PyCharm 用同一个 `run_experiment.py` 运行配置逐个复跑对照和候选。模拟组沿用默认输入，真实组在运行配置中将 `--history` 指向项目内的 `temp/rag-real-holdout/history.json`，用 `--queries` 分别指定两份真实查询清单。真实历史留在本机，Git 随每轮记录代码提交、数据指纹、配置和逐题结果。
3. 每题记录候选里的正确证据、排序位置、预算内实际装入的证据、镜号/字段/状态、用量和耗时。正确项在候选里就能区分排名或打包失败，正确项缺席就检查筛选。锁定候选参数后再打开留出题评分。

### 通过标准

| 指标 | 预先设定的门槛 |
|---|---|
| 当前真实对话的命中 | 近处 ≥ 7/8，旧改稿 ≥ 6/8，同会话新问法 ≥ 5/8。命中要求指定证据及必要的镜号、字段和状态进入预算，能支持问题所指的版本 |
| 当前真实对话的缺证据题 | 原题和新问法合计最多误召回 1/6 |
| 模拟回归 | 近处 ≥ 8/10，回查 ≥ 4/10，缺证据误召回 ≤ 1/5。带和不带回执的状态断言全对 |
| 新冻结的留出题 | 旧改稿命中 ≥ 75%，缺证据误召回 ≤ 25%。最小 8 道正例和 4 道缺证据题对应至少 6/8 和最多 1/4 |
| 明确引用与隔离 | 真实 8 条、模拟 10 条 ID 正例全对，未知 ID 返回空，未来和跨会话证据 0 条 |
| 输入和效率 | 所有题的历史证据 ≤ 6,000 字符。在同一机器和已加载语料的条件下，报告查询解析、筛选、排序和打包耗时的 P50/P95，当前 27/50 轮验收 P95 ≤ 50 ms。加载语料耗时单记 |

缺证据题里，实际装入任一候选就算误召回。近处、回查及留出组只按可见证据评分，正文和结构化记录保留的原值、新值要与来源一致。文中的门槛是实验设计值，跑完以后填实测。

### 如何接着调整

| 本轮发现 | 下轮单独改什么 |
|---|---|
| 正确记录在筛选后消失 | 查镜号范围、字段别名、状态来源和截止轮，修正对应的提取或过滤规则 |
| 候选已包含正确记录，替换词或同义说法搜不到 | 固定候选范围和预算，先测小范围同义词归一或新的词面排序，每轮只改一项 |
| 明确的动作、物品或否定条件对不上却返回了记录 | 固定候选和打分，增加必要词、否定条件或并列冲突的返回门槛，再跑无证据组 |
| 正确证据排在前面但没装进预算 | 固定排序，单测更精简的字段证据打包，并复核来源和新旧值 |
| 新增轮次后命中下降或耗时变长 | 核对候选覆盖和各阶段耗时，保留同一批目标题，增加对应类型的干扰轮，再针对瓶颈试索引或排序 |

每轮根据失败题直接开始下一轮，并在同一个项目里用 Git 分支保存对照。留出题揭晓后若需要继续调规则，这批题进入回归，下一次验收用新冻结的题。达到预设门槛后再给出适用范围、漏检例子和复跑方法。

## 持续实验的停止条件

实验轮次结束后，提交语料指纹、代码、运行参数和逐题结果。由失败记录找出下一个可验证的原因，从可复跑的基线建 Git 分支，在同一个离线检索项目里切换分支并直接开始。失败或局部改善仍进入下一轮。多个假设可各自用分支记录，同组对照固定数据、查询、证据预算和评分口径。只有候选达到预先写下的验收线，并在留出的现实问法上复跑通过，才能结束当前目标。原始问题和失败题保留在记录中，追加新数据时标明真实、脱敏转写或模拟。

### 历史记录中的本地模型验收单

本轮适用范围是当前短视频项目中对历史分镜改稿和应用记录的回查。普通连续追问继续使用最近会话，明确消息引用继续用 ID。真实对话以 AI 改稿为证据，已应用状态只从已有回执确认。真实原文留在本机。

- 第一轮续跑只改证据打包。排序、前 3 名和 6,000 字符预算固定。真实近处从 6/8 恢复到 8/8，已命中题保留，压缩后镜号、字段和新值与原始改稿一致。
- 最终候选在同一预算下，真实组近处至少 7/8、回查至少 6/8；冻结的 8 个新问法至少命中 5 个。真实原题和新问法的 6 条缺证据题最多误召回 1 条。作为模拟回归，近处至少 8/10、回查至少 4/10、缺证据误召回最多 1/5。
- 明确 ID 的正例全对，未知、未来和其他会话的证据返回空，打包不超预算。复跑时检查命中的是指定消息证据，而非同轮里另一条被投影掉的消息。对语料、模型和运行方式如实限定结论。
- 对分镜、选图和资产等其他类型的聊天，先添加对应的真实案例再扩展目标；对现有样本来说，同一会话的新问法用于检验表述变化，跨项目泛化需要独立会话。

开跑前冻结 [真实改稿新问法](real_validation_queries.jsonl)。发现排名正确却裁剪失败时先试打包；证据未进入候选时再改变取证或排序；缺证据题有误召回时独立检查证据校验。只在需要用户授权、缺少必要数据且无法构造有效替代、或运行环境无法恢复时停下说明阻塞。

## 已完成的本地模型对照

**明确 ID 直取，连续追问用最近轮次，回查旧改稿用本地模型选有依据的记录。** 只在当前会话内查截止时点前的已完成轮次。普通追问所需的近处历史沿用最近 3 轮。出现明确消息 ID 时由程序定位。需要回查旧改稿时，程序从已返回的结构化改稿和实际应用回执中提取候选，最多保留最近 12 份。一次只检索一题，模型最多选择一份改稿并返回 1–3 个证据片段编号。多个候选且首次选中时，倒序放入同一批候选再查一次。两次指向同一份改稿时，程序回取原记录并校验来源。其余情况可请用户补充镜号、改动或版本线索。

打包时优先保留整轮证据。遇到过长改稿，保留来源 ID、解释改动的正文和完整的结构化改稿，压紧 JSON 并去掉可由改稿还原的重复受影响镜头列表。单次历史证据上限为 6,000 字符。回执支持“已应用”，只有 AI 改稿时状态为“应用未确认”。当前验证范围是回查一份分镜改稿。普通追问和明确 ID 走独立路径，向量索引留待数据规模或候选覆盖需要时再评估。

## 基线预检

主对照 B0 固定取最近 3 个已完成问答轮，按整轮返回证据，程序记录随所属轮保留。取 3 轮是这次实验的明确设置。B1 调用现有的消息 ID 查找函数，在可见历史中根据用户提供的改稿消息 ID 取回完整一轮。交互演示会把该轮展开成整个案例，这次评分只看检索实际命中的轮次。

**实验设置。** 每个案例的程序应用记录是唯一的必需证据，共 10 个目标。对每个目标测两个查询时点：近处组设在该案例第 5 轮开始前，可见历史截止于第 4 轮（含应用记录）；回查组设在全篇第 50 轮结束后。B1 在两组都接收已知的改稿消息 ID，即 `m8、m18、…、m98`。历史只有当前实验会话。命中定义为返回的轮次包含该目标应用记录。由于每个查询只有一个必需证据，此处 Hit 和 Recall 的值相同。

| 对照方法 | 近处组命中 | 回查组命中 | 解释 |
|---|---:|---:|---|
| B0 最近 3 轮 | 10/10 | 1/10 | 回查时只覆盖最近的第 10 个案例，命中 `p10` 所在的第 49 轮 |
| B1 明确 ID 查找 | 10/10 | 10/10 | 已知改稿 ID 时，能取回该轮及它的应用记录；未知 ID 和尚不可见的 ID 均返回空，各核对 1 条 |

**这组基线回答了什么。** 在这组样本的两个查询时点，最近 3 轮够用的范围由证据位置决定。B1 证明已知 ID 的引用路径能找回指定记录。B1 使用了额外的已知 ID，因此这两个分数不能直接说明哪个方法更懂自然语言。这是基线预检。自然语言问题下的词组与二字匹配见首轮报告，本地语义检索见上方的对照表。回答阶段单独评估。

**当时拟定的自然语言对照。** 用同一份历史和同一组 20 个「目标记录 × 查询时点」，为每个目标写一条自然语言问题，标注正确的应用记录 ID。近处与回查可使用同一句完整问法。B0 和关键词候选都接收同样的问题，最多返回 3 轮。评分时按近处、回查分别统计，逐条列出新增命中与错镜。未知、未来及有同词干扰的查询应另列。B1 继续用来核对引用路径。

## 1. 根据要验证的问题生成数据

优先从当前 Agent 里选取符合任务的真实会话，在本地冻结快照，保留历史顺序和可核实的改稿或回执。缺少某种问题、干扰项或长度时，按实际讨论方式补生成相似会话，记录真实与模拟来源并分别报告效果。先写一句可以被实验推翻的假设，再选择对话内容和轮次。例如「给定当前镜号和明确关键词，关键词检索能比最近几轮找回更多被长时间隔开的已确认改稿」。写好对照方法和预期证据后再造样本。

| 想验证什么 | 怎么设计对话 | 轮次怎么定 |
|---|---|---|
| ID、范围和状态能否准确定位 | 写少量有明确镜号、字段、改稿和应用记录的完整案例，加入错误 ID 和不同会话复用镜号 | 先用 2–5 轮做冒烟，覆盖条件后即可开始 |
| 对话变长会不会漏掉早期修改 | 固定目标案例、查询和标签，在目标记录与查询之间增加无关讨论和词面相近的干扰项 | 可从 20、50、150 轮起步，按实际输入长度调整 |
| 同义表达能不能找回来 | 编写「推门」与「跨门槛进入屋里」等表述不同但指向同一事件的查询，同时写同词不同镜的反例 | 固定轮次与目标位置，只改变问法和干扰类型 |
| 能否找到后来真正生效的版本 | 同一镜头依次出现建议、确认、改稿、应用及后续再改。加入放弃、拒绝应用和撤销案例 | 以状态变化完整为准，每种状态至少有一条可核对的样本 |
| 能否处理指代和跨镜依据 | 加入「刚才那个」「改回上一版」以及需要同时查前后两镜的问题。相邻讨论里保留可消解指代的信息 | 先构造短样本，确认正确后拉长目标与当前问题的间隔 |
| 换故事或真实讨论后是否还有效 | 增加另一份故事、换分镜编号与术语，再用脱敏历史做留出验证 | 分别记录每份语料的轮次、案例数、长度分布和来源 |

### 生成一份可重放的数据

1. **先造底稿。** 给镜头固定镜号和字段，保留用于判断衔接的相邻镜头。状态跨案例延续时，下一案用上一次应用后的版本。
2. **再写对话。** 明确谁提出问题、哪条是建议、用户同意改哪些字段、AI 返回什么改稿、程序何时应用。让追问承接上文。只有确实有比较或追问的场景才增加轮次。50 轮基线的「10 案例 × 5 轮」是一种固定流程样本，其他语料可采用长度不同的案例。
3. **按底稿重放。** 程序用镜号和固定字段名应用结构化改稿，从前后状态计算差异。确认范围、改稿键、实际差异键要完全一致。保留拒绝和撤销的过程证据。
4. **独立标注查询。** 每条查询记录其会话、历史截止位置、查询类别、必需证据、可选证据和预期行为（回答、澄清、证据不足）。标签由人从底稿与历史记录确认，作为实验答案单独保存。
5. **检查时间边界。** 对一个历史时点的查询，只开放此前可见的消息。让一部分难例晚于调参样本，并按案例或故事划分调参集和留出集。跨长度对照保留目标及其相邻指代线索，并记录目标距查询的轮次和 token 间隔。核对为长度实验新增的干扰项没有改变正确答案。

建议给试验数据分开写版本。`history.json` 存历史；以后可用 `queries.jsonl` 单独存问题和预期证据；每次运行记录语料版本、轮次、消息数、目标距离和版本对应的提交。已有历史的 `id`、`turn_id`、`role`、`content` 可继续作为基础格式。可重放的现有案例已经把底稿、确认范围、改稿和差异放在结构化内容块里。评估用标签与预期答案只提供给评分程序。

**生成请求可以直接套用这一段。**

> 生成用于检验【假设】的分镜历史。设定【故事】【案例数量】【总轮次或轮次范围】【目标证据分布】【干扰类型】。为每个涉及改稿的案例保留修改前记录、用户确认范围、结构化改稿和程序差异。另给【查询数量】条查询，标注其可见历史截止位置、必需证据 ID 和预期行为。相同镜号的未应用草稿与已生效版本要可区分。逐条检查证据在查询时点已经出现，改动数据可以重放。输出每类样本的数量以及至少一条例子供人工抽查。

## 2. 从精确查找到 RAG

生产入口适合放在短视频会话读取历史之后、组装本轮 Prompt 之前。第一阶段在离线实验里验证取证逻辑，评价单位先定为「完整问答轮」；同轮程序记录随问答一起保留。交互演示展示整个案例，评估时仍按实际送入模型的消息或轮次计分。跨轮问题可以由多个证据共同满足，必要时针对这类查询单独测按案例检索。

| 版本 | 方案 | 这一版回答的问题 |
|---|---|---|
| B0 最近历史 | 本次实测固定取最近 3 个已完成问答轮 | 基础策略能处理多少依赖近处上下文的问题 |
| B1 精确引用 | 已测按消息 ID 定位所属轮次；按镜号、字段或生效状态定位可作为后续扩展 | 确定性查找与时点隔离是否正确 |
| B2 关键词 | 在当前会话中搜索问题和回复的词组；对明确短词用子串匹配，必要时加中文二字相邻匹配和镜号字段加权 | 同词重复、旧问答和远距离查询能否找对 |
| B3 混合召回 | 将已验证的精确路径保留，在关键词候选不足时用向量补充语义候选，再去重、筛选和排序 | 同义改写的增益能否抵消误召回和延迟 |
| B4 受控 Agent | 只有首轮证据不足或问题确需跨镜核对时才追加检索；实验开始前限定轮数、候选数和输入预算 | 自适应追加查询能恢复哪些之前查不到的必要证据 |

**首版 Prompt 数据流。** 当前问题和必要的最近轮次 → 识别显式 ID、当前镜号和状态 → 查旧历史 → 按作用域、时点、生效状态筛选 → 去重并按预算装入 → 生成回答。模型读到的内容包含当前问题、当前项目或所选镜头状态、必要的最近轮次、带来源 ID 的历史证据。讨论旧修改时，保留「历史建议」「已确认」「已应用」的区别。证据缺失时按查询类型给出澄清或证据不足。应用仍由程序按用户确认范围处理。

如果要看 RAG 的实际收益，完整历史可以在装得下的短语料里作为另一条对照。长语料采用相同上下文预算下的最近历史策略作为主对照。特意测试完整历史溢出时，记录拒绝、截断位置和遗漏证据，保留这一结果。

### 每一轮怎么做

1. **写实验单。** 写清假设、一个自变量、对照版本、固定项、样本和通过门槛。
2. **做手动冒烟。** 在 PyCharm 运行 `demo_history_retrieval.py`，输入 `p4` 或 `m38` 查看现有案例。核对第 4、5 镜从旧动作到新动作的差异，再试一个不存在的 ID。新语料按实际保存的 ID 查询。
3. **先单测检索。** 对同一批标注查询依次运行对照与候选，记录排序、分数、裁剪前候选、预算裁剪后证据、命中或失败原因与耗时。可以先用表格人工记录，样本多了再批量运行。
4. **核对 Prompt 证据。** 纯检索实验到证据打包为止。后续若要评估生成质量，再用同一问题对照「无历史」「实际检索证据」「人工指定正确证据」，在相同模型和规则下诊断生成阶段。
5. **先复盘再加数据。** 按错误类型统计和记录查询 ID。选最常见、影响最大的一个原因写成新假设，本轮失败题可补为回归题。保留独立留出集来复核下一轮。

## 4. 评估指标与完成门槛

评估记录至少有：查询 ID、类别、历史截止位置、预期证据、检索候选、最终送入的证据、Prompt 大小、模型输出或程序差异、耗时、失败归类。相关标签与排名可借鉴 NIST 的检索评估做法；生成阶段独立看证据是否支持回答。 [NIST trec_eval](https://github.com/usnistgov/trec_eval) · [RAGAS 论文](https://arxiv.org/abs/2309.15217)

| 层级 | 指标 | 怎么判定 |
|---|---|---|
| 数据 | 样本有效率、重放通过数 | 清单、角色顺序、截止时点、证据 ID 均有效；涉及应用的案例能重放出同一份字段差异 |
| 检索 | ID 准确率 | 有效 ID 命中对应轮；未知或越界 ID 按预期返回无结果 |
| 检索 | Hit@K、Recall@K | 有证据题中，Hit@K 统计前 K 个结果至少命中一项必需证据的题占比；Recall@K 对每题计算「前 K 个结果中的必需证据数 / 该题必需证据总数」后取平均 |
| 检索 | 全证据覆盖率、Precision@K | 前者统计全部必需证据齐备的题占比，适合跨镜问题；后者用前 K 中去重后的相关条目数除以 K，少返回的空位置计未命中 |
| 检索 | 误召回和时点错误 | 分别报告无证据题的返回率、错镜/错状态率、跨会话和未来证据条数。无证据题单独统计，分母排除在 Recall@K 之外 |
| 上下文 | 裁剪后的覆盖率、输入量、溢出率 | 对实际送入的证据再算同一套覆盖率。记录输入 token 或字符、输出预留，以及实际溢出请求占比。同一对照统一计量口径 |
| 生成 | 答案正确率、证据支持率、正确澄清率 | 逐题核对镜号、字段、版本和动作；把关键断言与证据逐项对照；按标签检查缺证据或指代不明时是否澄清 |
| 应用 | 应用范围一致率、未授权改动数 | 对比实际差异的「镜号 + 字段」集合与用户确认集合，另核对新值等于改稿，报告集合外改动总数 |
| 效率 | 检索耗时、请求次数、输入量 | 同环境比较检索耗时中位数和 P95，样本太少时报告逐题耗时。模型阶段另记请求次数、端到端时间和输入 token |

**门槛先写在实验单里。** 确定性项目可以设为零容忍：明确 ID 查询全对、跨会话与未来证据泄漏为 0、未授权改动为 0、可重放案例全部通过。效果指标根据业务目标定，保留分母和每个类别的结果。小样本用「改善了哪些题、退化了哪些题」和通过数量表达。

例如第一轮可设：「同一批 20 条有证据查询中，关键词版在相同预算下使全证据覆盖至少多 3 题；旧版已通过的明确 ID 题全部保留；另外 5 条无证据题没有误召回。」这是一组可调整的门槛示例，正式比较前冻结。效率门槛同样提前设定，例如在覆盖提升的同时输入 token 中位数低于最近历史对照，P95 检索耗时留在项目可接受的预算内。

## 5. 看到失败后，下一轮改什么

| 观察到的结果 | 先定位 | 下一轮单独改一项 |
|---|---|---|
| ID 找错或出现跨会话、未来证据 | 检查会话作用域、ID 归属和检索时点 | 修元数据或过滤条件，用原查询复跑，加入复用镜号和截止时点的回归题 |
| 只在远处旧轮次漏掉，词面明确 | 检查索引或扫描范围是否真的覆盖旧问答 | 先扩搜索范围，在保留目标证据的前提下继续拉长对话 |
| 关键词命中了同词的其他镜头 | 看候选里是否有正确条目，是否被错误镜号排在前面 | 加镜号或字段约束，再测同词干扰集 |
| 同义表达经常漏掉，精确查找稳定 | 区分候选从未出现和候选排名靠后 | 只对这组问题试混合召回，记录新增命中及新增误召回 |
| 错把历史建议或已撤销版本当成当前结果 | 查证据类型、应用记录时间与版本关系 | 加生效状态筛选，再增加未应用或多次覆盖案例 |
| 候选中有证据，实际 Prompt 里丢了 | 比较裁剪前后证据集合与字符/token 开销 | 优先保留实际应用差异或必要字段，再测同一预算 |
| 人工指定正确证据仍答错 | 检查模型是否把历史提议和项目现状混用 | 调整 Prompt 中的证据标签或输出约束，保持检索配置固定 |
| 增加语料后变慢，命中率基本相同 | 分别量扫描、排序、模型调用和 Prompt 长度 | 扫描是瓶颈时试本地索引；模型调用是瓶颈时减少追加查询或压缩可选上下文 |
| 结果只在阿澈故事里有效 | 核对查询是否复用了造数模板或答案关键词 | 在另一份故事或脱敏历史上跑相同协议，保持算法与门槛固定 |

每轮结论写成：「在【相同语料和预算】下，【候选】相对【基线】改善了【指标/查询 ID】，退化了【指标/查询 ID】。本轮的明确结论是【保留、补实验或回退】。下一轮只改变【变量】，用【数据版本及门槛】核对。」如果结果不足以区分两个解释，先设计能区分它们的查询，再决定是否升级到向量或 Agent。

## 后续目标模板

> 按《分镜长对话 RAG 实验手册》的纯检索方案，用当前 Agent 的真实分镜对话为主、模拟样本补缺，冻结查询和留出题，以最近 3 轮和现有词组检索为对照，验证不用大模型的「镜号、字段和应用状态过滤 + 关键词排序」。复用同一个 PyCharm 实验项目，用 Git 分支记录每轮代码、语料指纹、参数和逐题结果，根据失败原因直接开始下一轮，直到命中、误召回、证据预算和时点隔离达到手册验收线，再给出结论和复跑方法。

## 首轮并行实验协议

要检验的假设是「关键词比最近历史更容易找回旧的已应用改稿，加入中文二字匹配后能多找回改写问法中的证据」。B0 取最近 3 轮。两个候选分支只替换排名方法，分别使用连续词组匹配、连续词组加中文二字匹配。语料固定为同一份 50 轮历史，查询固定为 10 条自然语言问题的近处与回查版本，外加 5 条缺证据题。每个案例的应用记录是唯一必需证据，标签独立保存在 [查询清单](queries.jsonl)。

本轮检测的是进入 Prompt 之前的历史检索。所有方法按查询截止轮次读取同一个模拟会话，最多选 3 个完整问答轮，再按同样的 6,000 字符预算保留整轮。搜索文本和计分逻辑固定。上下文字符数按带角色和 ID 的历史证据原文计算，未计入生成规则和输出预留。首轮先用一份模拟会话发现问题，之后用同一评估协议补测了 27 轮真实会话。

首轮晋级条件在运行前固定：

- 有证据题较 B0 至少净增 3 题，近处组保留 B0 已命中的 10 题。
- 5 条缺证据题返回空证据。明确 ID 的已知、未知和未来引用检查通过。
- 只统计实际进入预算的证据。分别记录新增命中、退化、错候选、预算截掉的证据和检索耗时。

在同一个离线检索项目中，用 PyCharm 切到对应 Git 分支后运行脚本。默认结果文件是 `experiment_result.json`，复跑已提交的实验时可把运行配置的 `--output` 指向已有的 `temp` 目录，方便对照结果。第一轮结果用于决定是否继续调优，阶段性方案可以作为下一轮候选。 [run_experiment.py](run_experiment.py)
