# 世界设定生成与作品参数

人物、势力、世界观、人物背景与标题推荐使用同一份作品参数。完整流程和断点继续也固定这份输入，任务启动后修改界面草稿或磁盘参数不会改变正在运行的要求。结构、场景和章节继续使用任务快照。

## 生成前选择参数

界面有未保存修改，或当前有效参数与磁盘文件不同，所有生成入口都会提供三个选择：

| 选择 | 行为 |
|---|---|
| 保存并生成 | 先校验并保存，然后启动；失败时停留在参数页，不调用模型 |
| 使用已保存参数 | 使用完整磁盘版本，包括人物与势力数量；当前草稿保留，没有保存过参数时不可选 |
| 取消 | 不保存，不启动 |

模型服务和后端仍使用当前明确选择的配置。选择旧作品参数不会恢复旧模型服务。

「世界设定」右栏的数量与作品参数共用保存状态：人物为 2–10 位，势力为 1–10 个；旧项目未记录数量时默认 8 人、6 个势力。分步生成、完整设定、完整工作流和断点继续均使用选定版本中的数量。数量越界时会在模型调用前报错。

## 要求如何生效

世界设定勾选项表示「必须体现」，取消勾选表示「不得引入」。未提供的参数不视为禁用。主角类型、冲突规模等枚举以中文描述传给模型。

生成前提示词包含全部有效创作要求，输出路径、后端和模型配置不写入作品要求块。显式传入的参数优先于磁盘值，历史显示字段名与内部字段名统一处理，避免同一字段出现两个不同值。

已有人工设定作为世界设定模块的输入时，会先检查其是否与当前参数明确冲突。发现冲突会指出相关参数和原文，保留人工内容并允许继续模块内生成。可修改参数、编辑设定，或重新生成对应内容。结构、场景、章节的原有依赖检查本轮不重构。普通手动编辑、保存、改名无需新增模型调用。

## 检查、修复与失败保护

人物和势力先做本地字段、名称、引用及精确数量校验，世界观验证正文与名称规则契约。通过后，再使用当前选择的模型检查参数符合性；主要人物背景逐份检查，只核对该人物相关要求及全局禁令。

每个候选必须关联具体参数，检查报告记录期望、实际内容、判断原因和证据。有可核对原文证据的明确违背会反馈给生成步骤修复，每个产物最多初次生成加两次修复。只有风格意见或证据不足时显示「需人工核对」，不会声称已证明完全符合。

每份产物最多初次生成一次、自动修复两次；相同问题重复出现时提前结束。已移除总请求次数、整轮时长及单次请求的 120 秒墙钟期限；网络连接和读写沿用 SDK 超时，自动重试关闭。暂时性网络故障在单次操作内有限重试，请求数与耗时仅用于记录。

达到上限后，格式可读取的候选仍保存为当前设定，覆盖前备份，显示「已生成，待修改」。检查服务异常或报告无法解析时显示「已生成，检查未完成」。用户可以编辑、再修复一次、重新生成或继续模块内下一步；「再修复一次」只执行一轮修复与检查。

无法解析的原始内容保留在「生成结果与草稿」，可以离线编辑、修复结构并采用，不覆盖已有有效 JSON。取消后不再启动新请求，已返回内容保留为草稿。没有取得任何内容或实际保存失败才报告任务失败，诊断和已取得候选保留。世界观登记表无法读取时只交付正文，保留原有效登记表并提示问题。正式产物和对应生成记录在同一事务写入，失败回滚。

完整世界设定流程会在「待修改 / 检查未完成」后继续；遇到尚未采用的草稿时暂停依赖该结构的自动步骤。用户仍可分步生成，后续使用当前已保存设定；需要使用草稿内容时，先修复结构并采用。已有内容不会因规则未通过被删除。

参数检查独立于正文质量闭环；正文质量选择「关闭」时，世界设定参数检查仍然开启。正常生成每份势力集合、人物集合、世界观、主要人物背景各增加一次模型检查调用；明确偏离时会增加修复和复查调用，使用人工设定作输入时还可能有前置检查。因此生成耗时与调用费用会增加。语义检查仍可能误判或漏判，需结合报告和手动编辑核对。

## 查看记录

在「世界设定」右栏点击「打开参数检查记录」，进入项目的 `system/generation_runs`。每个阶段运行保留独立目录：

| 文件 | 内容 |
|---|---|
| `parameters.json` | 生效创作参数、参数快照指纹、阶段及模型服务配置 |
| `prompts/0001.md` 等 | 本次真实模型调用的提示词，包括后续步骤、修复与复查 |
| `compliance/<检查类型与记录编号>/attempt_N_prompt.md` | 第 N 次生成或修复要求 |
| `attempt_N_candidate.txt` | 第 N 次候选，包含失败候选 |
| `attempt_N_review_prompt.md`、`attempt_N_review_raw.txt` | 检查请求和原始返回 |
| `attempt_N_report.json` | 逐参数结论及证据 |
| `attempt_N_structural_error.txt`、`attempt_N_review_error.txt` | 本地校验或检查服务失败原因 |
| `request_N_error.txt` | 第 N 次实际请求的网络错误 |

`system/lore_generation/results/<记录编号>.json` 记录当前交付状态、问题、原始候选、正式文件、实际请求数、修复数、耗时和退出原因。世界设定页的「生成结果与草稿」展示这些记录，重启后可继续查看。生成过程中异常退出的未完成记录会恢复为草稿。手动修改入口读取当前保存内容；再次修复也读取当前文件，不回退到最初候选。

完整流程的各阶段参数文件应具有相同的 `snapshot_sha256`，可据此确认使用同一份创作参数。失败信息也会指出诊断目录。记录保存在 `system` 下，不作为故事输入，不自动清理。

证据不足的提醒会出现在完成状态和「世界设定 → 待核对」，重启后保留；核对后可确认当前版本。原有手动编辑、备份、改名同步、设定指纹及下游待核对功能继续有效，详见[世界设定编辑](lore_editing.md)。

## 无界面调用与离线验证

`run_stage`、`run_stage_action` 保持原有调用方式，可读取已保存参数，并通过 `parameters` 覆盖部分值；传入 `freeze_parameters(...)` 后视为完整快照，不再补读磁盘。任务工厂接受相同的 `parameters`，完整工作流只在启动时合并一次。

参数与界面端到端的专项测试已随测试精简移除。当前保留 `tests/test_headless_stage_pipeline.py` 的生成入口回归、`tests/test_ui_params_store.py` 的参数存储回归及 `tests/test_ui_smoke.py` 的界面冒烟测试。此前完整验收作为历史记录，见[循环与端到端验收](lore_loop_acceptance.md)，不代表当前自动化覆盖范围。
