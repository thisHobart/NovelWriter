# 网文视频推广工作台：交互设计

文档版本：2.26；日期：2026-11-20；状态：「与 AI 讨论」重新整理发给 AI 的内容：规则分段，之前的对话只带文字和当时附带了什么，分镜整份附带、篇幅大时从离当前镜头最远处逐级缩短，“查看附带内容”显示完整请求，回复用镜号和“名称（状态）”、不写内部编号；原文、改写、提示词页也附带当前内容，输入框里的标签跟着页面变，见第 7 节。

关联：[架构设计](architecture.md)、[接口设计](interfaces.md)、[开发文档](development.md)。不恢复检查中心、逐项确认、人物绑定和人工处置流程。第 11 节为已实现的手动导图视频交互；媒体验证独立记录，不沿用历史文字验收结果。

## 文字任务停止与继续（当前行为）

改写、分镜及提示词页在存在有效未完成任务时显示“继续生成”，与“重新生成”并列，不新增任务管理页。继续沿用原任务和检查点；重新生成替代同类旧任务的恢复数据，但原有当前内容保留到新结果成功提交。资产整批和单资产任务归同类；每类仅一个可继续任务。镜头优化有自己的恢复任务。

点击底部“停止”后显示正在停止，等待当前请求返回并保存，再停止后续步骤。网络错误先自动重试最多两次，状态栏显示对象、原执行阶段、“网络重试1/2”和等待时间；认证、权限或参数错误直接提示。重试耗尽、主动停止及程序意外关闭后的未完成任务需要用户点击继续，重开和刷新不自动请求。状态注明具体资产、阶段、已完成数量；审阅的网络重试耗尽后保留候选，从审阅继续。请求结果不明时提示“继续将重试，可能重复计费”，点击继续直接重试，不另加确认。

恢复前先处理未保存编辑，再检查原文、配置／Skill、模板、上游和目标内容是否仍一致。修改导致旧任务失效时隐藏继续按钮并说明上次任务不能继续的原因，允许重新生成；不把其他原文的已生成资产当作当前任务成果。检查点不展示为历史版本，不提供人工审阅面板。聊天和 ComfyUI 视频任务保持原有停止、查询行为。

## 并行任务与目录入口

底部新增任务下拉框和运行数量，按通道展示本次会话最近任务的名称、对象和状态。
首个任务自动选中，后续启动不抢占选择；切换后显示对应进度和耗时，停止只作用于当前所选任务。
所选任务结束后保留结果并隐藏停止按钮，其他任务继续；保存、复制等通知不覆盖活动任务的停止入口。
项目、创作模式和公共服务配置在任一通道运行时锁定，关闭时统一检查全部任务。

同一镜头正在 AI 编写、审阅、修订视频提示词或停止收尾时，锁定其选图、工作流、参数和正文，
并禁用“生成视频”，注明“当前镜头的视频提示词正在编写”。其他镜头可继续准备和生成视频；
查询已存在的视频任务不受文字通道阻止。已经提交的视频使用原快照，图片或提示词更新不停止它。
任务结果不自动跳转页签，不覆盖其他镜头及其他编辑器的未保存稿。

“打开视频位置”打开当前项目 `short_video/media/videos`，没有视频或正在生成时也可点击。
目录不存在时点击创建；无法创建或系统拒绝打开时显示具体错误，不要求先生成视频。

## 1. 设计原则

用户操作围绕创作内容：导入、生成、阅读、直接修改、继续、复制与导出。AI 检查是生成 Agent Loop 的内部步骤；人物和场景关系由软件维护。人工检查就是阅读并修改文档，本期不建立人工检查表、评分、接受理由或审核日志。

每个工作区只有一个主要下一步操作。信息仅在帮助当前决策时出现；版本 ID、引用 ID、规则集、请求数、来源哈希属于内部数据，不占主界面。保存与生成状态使用简短文字。

滚轮只用于滚动内容，不修改数值或下拉选项，即使控件已聚焦也不改变参数。分镜时长、生图并行数、视频参数和服务／模型选择均遵守这一规则；直接输入、键盘和点击操作保留。

不把已移除功能集中塞进“高级面板”。人工评审记录、审计看板、绑定管理等当前没有明确需求，先取消。生成后残留的具体问题可以在正文旁提示，不形成另一套操作流程。

## 2. 四个工作区与统一布局

| 编号 | 工作区 | 用户的核心操作 |
|---|---|---|
| P-01 | 原文 | 粘贴／导入、选择内容、手动选择可选 Skill |
| P-02 | 改写 | 小说推文与视频文案两个标签页，生成、阅读、修改 |
| P-03 | 分镜 | 生成分镜、编辑镜头内容和时长 |
| P-04 | 提示词 | 查看、编辑、复制提示词；镜头标签导图并生成视频；新增“资产图片”标签按视图勾选生图，见第12节 |

原文页移除赛道及全部创作设定表单，包括标题、受众、基调、人称、目标字数／时长和必需禁止内容。保留文章输入、导入、改编范围、保存与“生成小说推文”入口；该入口改编已有原文，不按设定从零写故事。

Skill 下拉框目前有“不使用 Skill”和“短视频内容分镜”，默认前者；Agent 不自动选择。用户选择后保存，后续分镜生成、检查和修订才使用该 Skill，小说／视频文案、资产和聊天不注入。选择持久化到当前项目，切换项目按各自选择显示；旧项目没有字段时不使用 Skill。查看、切换和保存不调用模型，点击生成前先保存本页编辑。旧创作设定保留在存储中，本页不再编辑或覆盖。

空原文在编辑器旁提示。无法解码时提供编码选择；超长内容在超限时提示到原文页缩小改编范围，不能悄悄截断；暂不提供长文分段。全文／选区是用户选择，软件负责偏移映射。

小说推文页的主要按钮为“用这版生成视频文案”，视频推广文案页为“用这版生成分镜”。原文页点击“生成小说推文”才启动第一阶段，单纯切换工作区不发起生成。第二阶段明确使用当前小说推文，两阶段内容不能合并。用户点击“用这版生成……”即选择当前可见稿件作为下一阶段输入，不再先“检查”、再“确认”、再“继续”。有未保存编辑时先保存并成功落盘，然后启动；保存失败保留编辑，不发模型请求。

默认第一次整理本条事件，第二次转换为可见动作、对白和必要旁白；不强制悬念、笑点或反转。小说编辑器末段标签由“结尾留钩”改为“结尾”，内部 cliffhanger 字段和旧稿保持可用。已有自定义阶段提示词继续优先，不因升级被覆盖，旧稿不会自动改写；重新生成后才使用新的默认指令。素材缺结果时指出缺失，不自动补结局。

原文对照按需展开，默认给当前稿件足够宽度。开头与结尾可由内部结构定位，但普通用户不需要编辑 JSON 或逐字段通过审核。视频文案允许直接编辑口播、对白和动作；软件维护所需结构。

生成按钮启动 Agent Loop：生成模型产出候选 → 独立校验模型检查 → 首次通过即采用；有问题则反馈给生成模型修订一次，再由校验模型检查。第二次无论是否仍有质量问题，均采用最新合法稿；问题完整记录在运行数据和日志，页面仅显示现有短摘要，用户可直接编辑。校验网络失败仍显示实际原因并保留候选，继续时只重做未完成检查，不算作检查通过。用户通常只看到“正在生成…”；耗时较长时可显示“正在调整…”，并能停止。没有“AI 检查”按钮或检查引擎选择器。

人工阅读发现问题时，可先在左侧讨论“开头如何更紧凑，保留事件结果”，再在右侧对应内容中手动修改并保存。聊天只提供建议，不直接替换字段。编辑器直接提供“编辑阶段提示词”，不提供历史版本、稿件历史恢复、另存候选入口。

表格是只读总览，五列：镜号、时长（如“8 秒”）、景别、人物、动作。每格只显示一行，鼠标停在格子上显示全文和这一镜的时间段。时长短于 4 秒或超过 15 秒标红（视频模型一次只能生成 4–15 秒），不在常规 5–8 秒内标黄，格子提示写明原因；没写动作的镜头显示“（未填写动作）”。拖动行可以排序；右键菜单有“在后面添加镜头”“拆成两镜”“与下一镜合并”“删除镜头”。由 AI 讨论修改、尚未保存的行为浅蓝底色。

选中一行后，下方表单按顺序列出这一镜的各项，名称在左：时长（0.5 秒一档，可设 1–15 秒，右边说明是否常规）、取景范围（直接写，或点“常用取景范围”选远景、全景、中景、近景、特写、主观视角）、镜头运动、场景、人物、道具、动作、对白（含旁白）和音效。文字框随内容变高；表格与表单之间的分隔条可以上下拖动。场景和道具绑定资产目录，只显示名称，要换时在与 AI 的讨论里提出。表单里的修改立即反映到表格，算作未保存修改，点“保存”才写入项目。

“拆成两镜”按时长对半分，两镜内容相同：后一镜的对白、旁白和音效清空，表格上方提示分别改写动作，并选中后一镜；不到 2 秒的镜头不能再拆。“添加镜头”（表格右上，或右键“在后面添加镜头”）在选中镜头后面加一镜 5 秒，沿用它的场景，其余留空；保存时没填的取景范围、镜头运动和动作在表单里标红，并选中这一镜。“与下一镜合并”只限同一场景：对白各行和人物合在一起，动作、旁白和音效两段接上（前一段没有句末标点时加分号），表格上方提示改写成一镜。

分镜的主要对外交付改为一整段视频描述。分镜页“查看原文”旁增加“复制分镜文本”，一次复制当前全部镜头，包括未保存编辑；复制前校验编辑器内容，但不保存、不调用模型。时间轴从当前镜头顺序与毫秒时长重新累计，支持 `[0s–1.5s]` 等短镜头，不能照抄示例中重叠的时间范围。表格和下方表单用于编辑，文件导出仅保留 Markdown。

整段文本固定六部分：视觉风格、场景概述、分镜、镜头要求、音频、限制。每镜包括时间段、取景范围、运镜、场景、人物及状态、关键道具和动作；旁白、对白（含说话者和画外音标记）、音效在音频部分按相同时间段列出。场景概述使用已保存目录及首尾动作；不额外调用 AI 编造故事摘要、音乐或视觉细节，不强制套用动作片、雨夜或科幻设定。

复制输出结构示例（具体内容从项目读取）：

```text
视觉风格：写实真人短剧，真实摄影质感，自然动作；保持人物、服装、场景和道具状态一致。

场景概述：地点：楼顶；主要出镜人物：主角；开场动作：主角奔向屋顶边缘；结束动作：主角落地翻滚后继续奔跑。

分镜（按时间轴依次呈现，总时长 4 秒）：
[0s–1.5s] 镜头 1：全景，侧面跟拍；场景：楼顶；人物：主角；主角奔向边缘，衣角被风吹起。
[1.5s–4s] 镜头 2：低角度近景，跟随运动；场景：另一座楼顶；人物：主角；主角落地翻滚，起身继续奔跑。

镜头要求：按各镜标注的取景范围和运镜执行，按时间点切换镜头，保持动作及空间关系连续。
```

生成分镜时自动提取必要的人物、场景和道具并维护关系，目录不再是用户必须生成和确认的中间成果。主表展示人名等内容，不展示 asset_id、绑定状态或关联完整性统计。

时长、顺序改变自动重算时间轴。表格上方的摘要写镜数和总时长，并对照 60 秒上限（成片要少于 60 秒），例如“共 12 镜 · 65.5 秒 · 比 60 秒上限多 5.5 秒”，达到或超过上限时用警示色，未超过时写“少于 60 秒”；项目设了短于 60 秒的目标时长时，“少于 60 秒”换成与目标的差距，例如“比目标 45 秒多 3 秒”，与目标不一致时也用警示色。只有原文页选择了“短视频内容分镜”，后台才使用其 H3 规则：常规单镜5–8秒，必要短镜可低于5秒，超过8秒优先拆镜，关注复杂度和前后衔接。未选择时使用普通分镜要求。5–8秒不是手动保存门槛；低于实际工作流支持范围的短镜需后续裁切，当前没有自动裁切。正时长、时间轴和引用校验保持。已有分镜不因选择改变自动重写，需要重新生成或直接编辑；分镜页不新增重复 Skill 开关或检查面板。

“镜头画面提示词”折叠区里的“重新生成”优化画面提示词。视频提示词旁的“AI 编写”结合当前分镜、相关资产及实际选图，按视频导演与 MiniMax H3 要求生成包含声音、负面约束的完整中文正文。正文成功保存后填入视频提示词框，可继续手动修改并一次复制。复杂动作的拆镜建议进入现有审阅反馈，不混入正文，也不自动修改分镜。

“镜头”标签顶部一排镜头号（01、02……）切换镜头，一行放不下时接着排到下一行：已有视频的镜头号右上角带绿点，最近一次失败带红点，正在生成带蓝点。下面是镜头卡片：“镜头 01”“分镜 N 秒”、两行动作（悬停看全文），以及“已保存 · 检查通过”，或“检查发现 N 项问题”按钮，点开逐条列出问题和建议；只有其他镜头有问题时写“其他镜头有 N 项问题”。来源已更新、尚未编排提示词、上次任务未完成或不能继续、画面提示词有未保存修改等提示在卡片底部单独一行。没有分镜时隐藏镜头号和卡片，只显示页面状态。

本镜所需的场景、人物、道具不再单独列表。点图片位置或“换图”弹出选图菜单：“本镜资产”按“场景 · 名称（状态） · 视图”列出当前镜头实际引用对象的各视图，已有图片的带缩略图，没有图片的写“（未生成图片）”并灰显；“项目图片”带缩略图，点名称选用，“×”从列表移除（文件保留）；最后是“从文件选择…”。选中才填入这一个位置，不替换其他位置、不改视频提示词。资产提示词正文在人物／场景／道具标签查看和复制。

## 7. 左侧对话

保留多轮对话和项目隔离，输入框提示为“输入消息，与 AI 对话”。输入框内上方的标签写明这次发送附带什么，跟着右侧显示的页面变，默认附带。附带的是页面上现在的内容，包括未保存的修改；聊天不保存、也不校验页面：

- 原文：“附带原文 · 全文 621 字 · 已保存”（选了改编范围时写“改编范围 N 字”），附带改编范围内的原文和赛道、创作要求；几段之间用“……”隔开，超过 20,000 字只带前面部分并注明没带的字数。
- 改写：“附带小说推文 · 已保存”或“附带视频推广文案 · 含未保存修改”，附带当前子标签的稿子（按表单的开头、正文、结尾，或各块的口播、动作、对白）和这一步用到的项目要求，不附带原文。
- 分镜：“附带分镜 · 第 N 镜 · 已保存”，没有选中镜头时不可点，见下段。
- 提示词的人物、场景、道具：如“附带人物提示词 · 阿澈（旅人状态） · 已保存”，附带当前对象这一状态的设定和各视图的正向、负面提示词，标出正在显示的视图；同名对象写成“寻井人·2”，与 AI 回复里的写法一致。
- 提示词的镜头：如“附带第 3 镜视频提示词”，附带本镜和前后镜的分镜（前后镜用来核对衔接）、视频提示词框里的当前文字、已选参考图片和 <Picture N> 的对应、首尾帧、画幅、分辨率和时长（写明与分镜时长是否一致）；提示词里的 <Picture N> 没有对应图片时注明。
- 资产图片标签不附带，不显示标签。

点标签上的“×”改为普通聊天，点“+ 附带当前原文”（各页写法不同，如“+ 附带本镜视频提示词”）恢复；在一页取消附带不影响其他页，回到这一页时仍是取消。页面还没有可附带的内容时按钮不可点，悬停说明原因（如“先粘贴或导入原文”“先生成提示词”）。标签太长时用“…”缩短，悬停显示全文和附带内容清单。取消附带或没有可附带内容时，只发送你的消息和之前的对话。

分镜页附带整份分镜（含未保存修改）：每镜按表单写成文字（时间段、时长、取景范围、镜头运动、场景、人物、道具、动作、对白、旁白、音效，场景、人物、道具写“名称（状态）”），开头写明全片合计时长、60 秒上限、项目目标、常规单镜 5–8 秒和视频模型一次能生成的 4–15 秒，以及当前选中的镜头和消息里提到的镜头（如“第 2、5 镜”）。另附资产目录（各对象名称与状态）、当前镜头和提到的镜头用到的资产基础设定、这些镜头引用的原文片段（补成整句，最多约 6,000 字）和项目要求，不带视频推广文案。分镜超过约 20,000 字时，当前镜头、提到的镜头和它们的前后镜保持完整，其余镜头从最远处起依次把动作和音效截到 60 字、只留时长场景人物，最后整镜不带，资料末尾写明哪些镜头缩短或没带。发送时重新读取编辑稿，不因聊天保存或校验整份分镜。AI 说明修改时用表格和表单里的名称（取景范围、镜头运动、动作等）和“第 N 镜”，场景、人物、道具写资产目录里的“名称（状态）”，不写内部编号；取景范围填写远景、中景等简短名称，镜头运动用一句话；每个要改的镜头写“时长：当前 X 秒 → 建议 Y 秒”或“时长：保持 X 秒”并说明理由，有时长变化时最后写全片合计“当前 X 秒 → 修改后 Y 秒”，以及是否少于 60 秒、与目标差多少。改动涉及多个镜头时，AI 按全稿列出受影响的镜号和改法，缺失材料如实说明。

AI 建议修改镜头时（只改一镜也附；例如坠落物由毛绒小羊改为房子，要改好几镜），在回复末尾附受影响镜头清单，聊天里只显示“〔已列出受影响的镜头〕”，这条回复下方出现“受影响的镜头”卡片：每镜一个勾选框，写明镜号、要改的地方和改法，默认全选；建议时长和当前不同时，要改的地方写成“时长 5.5 → 7 秒”；资产目录里没有的对象单独提示，只会写进动作。点“修改所选镜头”自动发出“按清单修改第 N 镜”，本轮附带整份分镜（所选各镜保持完整）、“本轮要修改的镜头”清单（要改的地方、改法、建议时长）、资产目录、相关资产设定和原文片段；AI 按建议时长改，清单没给时长的镜头按动作与声音估算。AI 先逐镜说明，再给出各镜修改后的各项字段，用镜号和“名称（状态）”书写；程序按发送时的镜头顺序和资产目录对应回镜头与资产，逐镜检查取景范围等必填文字、名称与状态、画面人物与说话人、时长，名称对不上时写明原因（例如目录里没有这个名称，或同名对象要写成“寻井人·2”）；不通过时自动让 AI 修正一次（作为同一对话的下一轮），仍不通过的镜头标“未通过检查”。之后在该回复下方显示“AI 修改结果”卡片：每镜一行“第 N 镜 · 改了 N 处”，第一个有改动的镜头默认展开，逐列列出原来（划线）和改成，其余点“展开”查看；勾选后点“应用到分镜”写进分镜表格，已写入的镜头标“已写入分镜”，表格中这些行浅蓝底色，算作未保存修改，点“保存”前不写入项目；AI 修改之后该镜又被编辑过时，应用前确认是否覆盖。应用后没有其他编辑时可点“撤销应用”恢复原样。卡片只跟在最新一条完整回复下；有了新回复，旧卡片收成一行，例如“受影响的镜头 2 · 已按第 1 镜发出修改”。只改已有镜头的内容，不增删、拆分或合并镜头，不新增资产；离开分镜页时隐藏。之前保存的旧格式回复（带内部编号）仍能显示卡片。

用户消息靠右显示在浅蓝气泡里，附带页面内容时上方标注当时附带了什么，如“第 3 镜 · 含未保存修改”“原文 · 全文 621 字”“第 3 镜视频提示词”，过长时缩短、悬停显示全文；AI 回复靠左，按 Markdown 显示标题（不大于正文字号）、加粗、列表、引用、代码块和表格；用户输入按原文显示。等待回复期间先显示刚发出的问题和“正在回复…”，“发送”变为“停止”，点它停止本次回复。输入框随内容增高，最多约五行后滚动。面板默认宽 384，拖动后的宽度按项目记住。当前编辑稿是修改底稿，历史建议不代表已经应用。每条消息独立排版，未闭合的代码块不影响后续消息，原始 HTML 不执行渲染，链接点击不替换聊天历史。消息区增加阅读行距；位于底部时跟随最新回复，向上阅读时保留滚动位置。存储和发送给模型的消息正文保持原样，完整附带资料不写入消息正文。

已有会话选择收纳进面板标题栏的对话按钮：菜单列出最近 12 个对话、“更多对话…”和“重试上次问题”，旁边“新对话”。发给 AI 的内容依次是：规则（分“通用要求”“本页要求”两段，分镜页另有“输出格式”）、之前的对话（你的消息和 AI 回复交替）、本轮附带内容，最后是你的消息（写在“【我的问题】”之后）。之前的消息不再重复当时的资料，只在开头写明当时附带了什么，如“〔当时附带分镜，选中第 3 镜〕”“〔当时附带原文 · 全文 621 字〕”；AI 回复里的镜头清单和修改结果换成一句说明，如“〔列出了受影响的镜头：第 2–4 镜〕”。默认请求容量为 48,000 字符，包含规则、之前的对话和本轮附带内容；超出时你的消息都保留，先把较早的 AI 回复缩成第一段（注明后面约多少字省略），再省略较早的回复，然后才轮到最近一轮回复，最后才去掉最早的整轮对话；只影响本次发送，历史仍可阅读。这时输入框下方会提示，如“较早 3 轮的 AI 回复只带了开头，你的消息都带上了”。规则、本轮消息和附带内容本身仍超限时，提示缩短消息或附带的内容、或点附带标签上的 × 取消附带，不静默截断；此时新建对话不能解决。失败、取消、中断或缺最终回复的轮次不带入新请求。

附带时输入框下方的“查看附带内容”打开“发给 AI 的内容”：开头写明共多少字、上限多少和各部分字数，规则默认收起（点“规则（N 字）”展开），之前的对话按“第 N 轮 · 你”“第 N 轮 · AI”列出，缩短或没带上的回复会标明，最后是“本次发送”的附带内容和消息；只读，不保存也不发送。

发送前先做只读预检，容量／配置错误不留下 pending 消息。预检成功后通过后台任务保存本轮用户输入，等待一次完整回复再刷新；当前没有逐字流式输出。停止期间已完整返回的回复仍保存为 cancelled，后续历史过滤该轮。重试上次问题只将文字放回输入框，用户核对后再次发送，不自动重发。重启只标记孤立的未完成消息，不主动请求模型。

除分镜页按清单修改镜头外，对话只用于讨论和提供建议，不提供“作用目标”、字段选择或“应用修改”入口：原文、改写和提示词页的回复可选择复制，用户在右侧对应内容中手动修改并保存，不能将整段讨论自动替换为某个字段。对话菜单仅保留新对话、选择已有对话和重试上次问题。普通回复不经过生成 Agent Loop；页面中的生成和重新生成仍执行自动校验与有限修订。

## 8. 导出与异常

点击统一“导出”按钮后只选择内容与保存位置，固定导出 Markdown（.md），取消格式选择框。分镜采用上述六部分段落格式，不再输出九列 Markdown 表；不要求用户选择“检查引擎”或完成审核签字。

导出前自动检查文件与内容结构。缺少内容时提供“导出已有内容／返回补充”；仅导出当前有效内容，不导出历史稿件。取消把人工确认、全部 warning 处置、确认所有视图作为导出门槛。无法形成合法文件的结构错误才阻止并定位。

| 情况 | 用户反馈 |
|---|---|
| 生成和自动修订正常进行 | 显示具体操作、对象与阶段，例如“资产提示词生成中…｜老宅 · 自动审阅”；可停止 |
| 网络自动重试 | 显示具体操作、阶段、重试序号及等待时间；等待时点击停止立即结束，不占质量修订次数 |
| 请求最终失败 | 区分限流（429）、认证、权限、服务异常、连接失败和超时；不再统称“短视频任务未完成”或直接堆放英文异常 |
| 批量任务中断 | 说明当前资产、失败阶段和已完成数量，例如“资产提示词生成中断｜老宅 · 生成：接口限流（429）；本次已完成1/3项” |
| 自动审阅／后续修订网络失败 | 网络重试耗尽后保留检查点与最新合法候选，显示“分镜生成中断｜自动审阅：请求超时；候选已保存，可继续生成”；不将候选误报为已提交的当前分镜 |
| 达到重试上限，检查仍未通过 | 显示一条具体问题摘要和问题数量，完整反馈进入日志；不新增问题清单或确认流程 |
| 已完成项有质量问题，后续项中断 | 已完成项保留各自检查结果；任务显示当前中断位置及已完成数量，继续时处理未完成项 |
| 输出结构无效且格式修复耗尽 | 保留当前内容，说明未取得可用结果；可重新生成，不提供继续入口以重置修复次数 |
| 上游内容改变 | 清理依赖旧来源的下游内容，页面显示缺少内容并引导重新生成，不提供沿用旧稿 |
| 保存冲突／磁盘失败 | 保留编辑，说明怎样恢复；不覆盖新版本、不继续收费请求 |
| 离开未保存编辑 | 保存／放弃／留在此页 |
| 手工修改保存 | 显示“已保存；当前内容尚未自动检查”，不继承修改前的检查通过状态 |
| 主动停止 | 明确停止哪项操作，只说明已确认保存的候选或完成数量；视频任务区分尚未提交与仅停止本地等待 |
| 远程提交／查询状态不明 | 黄色提示查询原任务，避免重复提交；视频已生成但下载失败时说明“视频保存未完成” |

状态栏保持单行，长摘要按可用宽度省略，不撑宽窗口；正文旁状态可换行。绿色表示成功，黄色表示已有可用内容但仍有问题、部分完成、主动停止或远程状态待确认，红色表示未取得可用结果或保存失败。界面不新增详情面板；原始异常和堆栈保留在日志，简明反馈存入原有运行记录。旧记录没有原因时如实说明“未记录具体原因”，不推测为网络失败。所有冲突均保留当前内容并提示核对，取消历史恢复引导。

每个内容键只保留当前一份。保存／重新生成替换当前内容后，清理旧文件及依赖它的下游。停止或可恢复失败保留最新临时候选供继续执行，已有当前内容保留；冲突或任务失效时清理临时恢复数据。这不提供稿件历史恢复。

## 9. 本期移除项与实现判断

移除：独立检查中心、代码／AI／人工标签、手动启动 AI 检查、人工评分与处理记录、人物绑定／重绑入口、资产目录确认、逐视图确认、单独编译确认、主界面版本与运行统计、独立项目总览与导出导航页，以及作用目标、应用修改、按意见重新修订、另存当前编辑为候选入口。

保留于内部：实体 ID、来源依赖、结构检查、AI 审阅、有限修订和任务故障记录。删除稿件历史保存与恢复能力。保留于用户界面：内容、直接编辑、聊天讨论、下一步、复制、导出，以及真正需要处理的异常。

验收主路径：导入原文 → 生成小说推文 → 直接编辑 → 用当前稿生成视频文案 → 生成分镜 → 生成提示词 → 导出。整个路径无需打开检查页、绑定人物、填写人工评审记录或额外点击确认版本。

## 10. 生成、保存和导出的实际区别

| 用户动作 | 当前执行行为 |
|---|---|
| 切换工作区 | 处理未保存编辑后展示内容，不自动生成下一阶段 |
| 生成分镜 | 后台先提取资产目录，再生成分镜，二者分别执行 Agent Loop |
| 生成资产提示词 | 按待生成项运行循环，由模型生成设定和各视图；初次镜头提示词由代码编排 |
| 保存人工编辑 | 本地校验，所有内容替换当前一份并清理失效下游；不请求 AI，分镜／设定保存后尝试更新镜头提示词 |
| 优化当前镜头提示词 | 使用当前镜头 ID 和固定优化要求执行循环，保留其余镜头 |
| 导出已有内容 | 可以跳过未生成内容；已选资产本身缺必需视图等结构错误仍阻止导出 |

提示词按对象和状态仅保留当前一份，各视图在这份内容中切换。保存编辑或重新生成会替换当前提示词，不再提供“更多／历史版本”及恢复入口，不再显示“基于旧内容，可查看和明确导出”，也不询问是否沿用旧提示词来源。生成失败、取消或发生编辑冲突时保留已有当前内容；资产提示词更新后重新编排对应镜头提示词。

导出界面仅提供 Markdown 文件，提示词随文字包输出当前内容。文件还会生成 `.manifest.json` 来源清单。普通聊天不把回复写回稿件；聊天内容若要进入生成输入，由用户自行编辑到相关业务内容或创作要求。

模块结构与核心生成流程见[架构设计](architecture.md)，会话输入与恢复契约见[接口设计的聊天部分](interfaces.md#22-聊天与分镜只读上下文)。

## 11. ComfyUI 图片与视频操作

### 11.1 配置入口

顶部“服务配置 → ComfyUI 工作流”进入项目配置，默认地址为 http://127.0.0.1:8188。工作流下拉框可切换已有配置；“新增”后填写名称、粘贴固定 API JSON，保存后在生成区可选。不再用文件路径配置视频工作流，预留的图片工作流不占 UI 控件。

```text
┌──────────── ComfyUI 工作流配置 ────────────┐
│ 服务地址：[http://127.0.0.1:8188         ] │
│ 工作流：[H3 参考图 ▼]             [新增] │
│ 名称：[H3 参考图                       ] │
│ API JSON：[粘贴或编辑正文……]            │
│ [测试连接]                [保存] [取消] │
└─────────────────────────────────────────┘
```

测试连接只校验服务、选中模板的节点与模型，不执行生成。保存校验 JSON 和适配关系。名称、JSON 及服务地址按项目保存；软件内置 MCP 桥接，无需另行部署服务。

### 11.2 镜头标签的实际布局

保留四个工作区。人物／场景／道具标签仍编辑文字；镜头标签整页是视频区：顶部镜头号和镜头卡片（见第 6 节），下面参考图片和首尾帧横跨整页，再下面左边视频提示词、右边视频卡片同一行（提示词框随卡片一样高），最下面是“镜头画面提示词”折叠区。视频区宽不足 680 时改为一栏，视频卡片排在视频提示词之后。排法只看宽度，改参数不会让卡片换位置。底栏左侧一行任务状态，右侧“生成视频”，远程状态待确认时多一个“查询原任务”。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 镜头 [01•] [02] [03]                                             │
│ ┌ 镜头 01  分镜 8 秒 ────────────────────────────────────────┐ │
│ │ 动作（最多两行）……                                         │ │
│ │ 已保存 [⚠ 检查发现 3 项问题 ⌄]                              │ │
│ └────────────────────────────────────────────────────────────┘ │
│ 参考图片 已选 2 / 3 · 编号按已选顺序   ┌ 视频 [已保存] ───────┐ │
│ [<Picture 1>] [<Picture 2>] [＋ 选择图片] │ ┌ 16:9 状态区 ┐     │ │
│ 名称 [换图][×]   [＋ 添加参考图片]     │ [打开视频][打开视频位置] │
│ 首尾帧 不占 Picture 编号（组合模板）   │ 工作流 [H3 参考图▼][配置] │
│ 视频提示词 [AI 编写][继续编写][复制]   │ 加速模式 ○             │ │
│ [完整可编辑正文……]                     │ 分辨率 [0.40]           │ │
│ 提示：结合当前分镜……                   │ 时长 [10] 分镜 8 秒 改成 8 │
│ › 镜头画面提示词 正向 · 负面           │ › 高级参数 采样步数、随机种子 │
├──────────────────────────────────────────────────────────────────┤
│ ● 视频已保存；实际时长 8.04 秒                       [生成视频] │
└──────────────────────────────────────────────────────────────────┘
```

图片区按有效连线生成卡片，自带 H3 参考图默认三个位置。卡片显示缩略图和文件名，左上角标出提示词代称“<Picture M>”；空位显示“＋ 选择图片”，底部写“图片 N · 未选”。点空位或“换图”打开选图菜单（见第 6 节），卡片上的“×”清空该位置。普通参考图可点“＋ 添加参考图片”，按钮写明还能加几张，最多九个位置，加好后页面滚到新位置；至少选一张即可生成，空位自动跳过。M 按已选图片顺序连续编号（标题旁写“已选 n / m · 编号按已选顺序”），例如第4个位置可能对应 <Picture 2>，与“图片 N”不能混用。参考图＋首尾帧工作流的首帧、尾帧单独成组，标题“首尾帧 · 不占 Picture 编号”，卡片角标写角色名称。清空中间位置导致已有提示词引用错位时，视频提示词下方立即提示“图片编号已变化……”，生成前仍要求核对修改。菜单里项目图片的“×”把该图从所有位置的列表中移除，已选中它的位置随之清空；图片文件保留，资产视图和已有视频任务不受影响；从“本镜资产”再次选用或从文件导入即恢复。暂不提供删除位置按钮；新增位置仅在当前项目、当前程序的工作流草稿中保留，不改写保存的模板。

组合模板仍显示三个参考图位置、首帧图片和尾帧图片，共五项；独立首尾帧模板仍显示两项。这两类不显示添加按钮，至少选择一张即可生成：支持只选首尾帧、仅尾帧、仅首帧、仅参考图或混合选择。空位不上传，未选帧的引导会从本次执行图中移除，保存的模板不变。Picture 编号仅按实际选中的参考图排列，首尾帧不占用编号；没有参考图时应使用首帧／尾帧角色名称，不可引用 Picture。每项可选已有项目图片或导入 PNG／JPEG／WebP，检查解码后复制到项目，原图不修改。更新粘贴的 JSON 后，初始输入数量随有效连线同步更新。

参数类型与默认值来自已适配模板，只有画幅和分辨率例外：每个镜头一律从“9:16 竖屏”和 1.00 百万像素开始，不管工作流 JSON 里写的是什么；镜头上改过的值按镜头保留。参数放在视频卡片里：工作流和“配置”、加速模式开关、画幅、分辨率、时长常显，采样步数和随机种子收在“高级参数”。种子支持 64 位整数，“换一个”随机生成。时长与当前镜头的分镜时长一致时旁边写“与分镜一致”，不一致时写“分镜 N 秒 改成 N”，点“改成 N”填入分镜时长；时长按模板帧数网格换算，生成结果可显示实际时长。应用内不播放视频：卡片的 16:9 区域只显示状态（未生成、生成中、视频已保存、生成失败及原因、待确认），“打开视频”用系统播放器打开生成的文件，“打开视频位置”打开目录。卡片宽 560 以上时状态区与参数左右并排。窗口较小时整页滚动，不压扁输入框；视频提示词至少200px，参数控件至少32px高。提示词、参数和选图按当前分镜／镜头及工作流隔离，切换后恢复各自本次草稿和滚动位置；项目切换清空临时编辑。程序重启后临时编辑不作为新任务自动提交。

参考图初始文案提供可编辑的 Picture 1 描述；参考图＋首尾帧及独立首尾帧使用相应模板默认文案。选中当前镜头、完成资产提示词并选好图片后，可点“AI 编写”。编写和修订时会把本镜选中的参考图和首尾帧发给支持多图输入的生成模型，独立校验模型检查文字。正文开头集中说明图片用途，后续按时间描述动作和画面变化。生成只改视频正文，保留左侧画面文字、分镜和选图，不自动生图或提交视频。

成功结果随当前镜头保存，匹配当前选图、工作流和时长时回填；重复刷新不覆盖后续手动修改。修改这些输入后保留正文并提示重新编写、核对。中断后，只有当前镜头与实际输入仍匹配时显示“继续编写”，从已有文字检查点恢复。用户可随时直接编辑或复制视频正文，留空时明确报错；“生成视频”冻结当前工作流、图片、正文与参数后提交 ComfyUI，不隐式调用 LLM 补写。

### 11.3 结果、停止与恢复

| 情况 | 界面行为 |
|---|---|
| 排队／执行／取回结果 | 通过现有状态栏显示阶段，无真实百分比时不伪造进度 |
| 正常完成 | 卡片标“已保存”，底栏写视频已保存；“打开视频”打开文件，“打开视频位置”在有项目时始终可用；服务提供时显示实际时长，不在应用内加载视频 |
| 提交响应丢失／远程状态不明 | 卡片标“待确认”，底栏出现“查询原任务”，点击查询，不自动重新提交 |
| 远程完成但文件下载失败 | 点击“查询原任务”重新获取文件，不重跑模型 |
| 点击停止 | 结束本地等待，说明 ComfyUI 可能仍在运行；之后可查询原任务 |
| 保存、节点或模型错误 | 保留原图和已有产物，显示具体错误类型与消息 |

界面按所选工作流与实际图片选择展示最新视频任务，普通参考图忽略空位；新任务保留旧文件，不提供完整媒体历史管理页。当前没有图片采纳、AI 图片检查、批量队列或成片编辑。普通聊天与 Markdown 导出保持原用途。

用户提供的组合 JSON 中 CreateVideo.chroma_subsampling 为 none，与当前本地节点枚举不兼容。软件自带副本已改为 auto；已有项目粘贴用户原文件时，需要同样把该值改为 auto，或粘贴软件自带的 minimax_h3_first_last.json。原用户文件不自动修改，已有保存的工作流也不自动替换。

## 12. 可选资产图片

顶部“服务配置 → 生图 API 配置”填写独立基础地址、密钥、模型，协议固定为 OpenAI 兼容 Images API；支持获取模型或手动填写。“检查连接”仅查询模型列表，不发送聊天或付费生图请求。

“提示词”内五个标签为人物、场景、道具、镜头、资产图片，整体仍为四个工作区。资产提示词生成成功后切到资产图片，但不自动生图；不使用此页、不配置或不勾选不影响文字流程。已有文字结果可直接列清单。无分镜显示先生成分镜，无完整提示词的行说明缺失原因且不可勾选。

表格按资产／状态／视图合并，列为勾选、资产及状态、视图、使用镜头、图片状态；默认不选。提供全选可生成项、清空、并行数（默认2，范围1～8）及“生成所选图片”。每视图一张。点击行在右侧查看对应提示词、图片、来源变化或具体错误；已有图片可重新生成，新结果保存成功前保留原图。

运行中逐项显示排队、生成、网络重试、待下载／解码、保存、成功或错误，配置和启动控件禁用。图片通道每次一个批次，批次内部并行；不阻止文字或 ComfyUI 视频任务。停止显示“正在停止，等待已发送请求返回”，保存已返回结果，不再启动新项。

点击有未完成结果的行可继续其原批次，即使之后生成过其他资产；已完成项跳过，有完整响应只处理下载／解码。未知项保持明确提示并取消原勾选，只有用户重新勾选启动才重新请求，可能重复计费。重新打开程序只识别中断，不自动执行。

选图菜单“本镜资产”中的图由准确资产视图匹配。提示词改变标注图片待更新，旧图仍可查看和手动使用；不会因切换镜头或视图自动选图。图片位置跟随当前工作流及新增参考图位置更新，首尾帧保持角色名称，Picture 编号继续按实际参考图顺序显示。
