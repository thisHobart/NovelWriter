## 独立短视频文字提示词 default-v3（2026-11-15）

按已确认方案更新现有文字链路，不新增 H3 提示词整理或媒体调用。第一次整理一个有必要因果和已有结果的事件，第二次转换动作、对白与必要旁白；目录仅提取视频实际对象，分镜按视觉与声音节拍拆解，资产保持多视角，镜头优化聚焦当前画面。允许忠实口语化与合理外化，不新增关键事实或结局，不强制爆款、悬念、反转或笑点。素材无结果时如实报告，不补造收束。

共享规则只保留事实、来源、资料隔离和JSON；对白、目录枚举、时长、资产视图等约束按阶段注入，演示与当前资料隔离。分镜结构样例不再把全目录人物、道具和视频块塞入第一镜。默认阶段引用升级为 default-v3；自定义模板仍优先，包括分块改编与最终合稿，旧稿、历史快照不改。只读核对当前项目没有已保存的自定义阶段模板。

保留 cliffhanger 字段／枚举作为结尾段，不做数据迁移；小说编辑器显示“结尾”，校验文案改为开头／结尾段。审阅按六类内容分别判断，格式修复只修JSON／字段／引用。分镜时长代码求和，提供超60秒、超范围目标和有效目标不闭合的 warning，手动保存仍允许正时长历史内容。镜头本地编排去除完全重复文字，并明确固定设定只约束身份、布局和状态，不要求同时可见。原文页与可选Skill机制不变。

验证：全量 **263 passed（17.03秒）**；本次7份生产文件 Ruff 与格式检查通过，文档链接和差异检查通过。新增离线回归覆盖闭合事件的四阶段生成与导出、合理改写的画外对白、仅声音人物不入画、边界总时长与目标提醒不阻止保存、素材缺结果时有限修订后仍为 issues、自定义模板不覆盖、精简的分镜结构样例、镜头文本去重且引用不变；既有长文恢复测试增加自定义模板用于分块与合稿的验证。使用临时项目和模型替身，未调用真实模型或生成视频；离线通过不代表实际成片质量已验证。

## ComfyUI 固定多工作流（2026-11-15）

依据已确认的[方案](comfyui_workflow_plan.md)，在现有媒体服务上实现 API JSON 粘贴、命名、多工作流保存与选择，及参考图 1～N／首尾帧对应输入。生成仍通过内置 MCP 桥接，不接入文字 Agent Loop。

| 文件 | 当前职责 |
|---|---|
| media_workflows.py | 项目工作流列表、旧配置读取、API JSON 依赖裁剪、两类 H3 模板、图片与类型参数映射 |
| media_service.py | 冻结工作流标识、全部图片与参数；逐图上传、绑定 JSON 副本、单次提交与任务恢复 |
| media_repository.py、comfy_mcp.py | 复用图片导入、原子保存、上传／提交／查询／下载，不增加中间生图功能 |
| comfy_settings.py | 地址、工作流选择、新增、名称与 JSON 粘贴、后台校验与保存 |
| media_preview.py、workbench.py | 工作流切换、按模板生成图片／参数控件、刷新配置、生成与本地播放 |
| workflows/、NovelWriter.spec | 打包参考图及新增首尾帧两份固定 API JSON |
| tests/test_comfyui_video.py | UI→后端→MCP→ComfyUI 的图片／参数、配置与任务恢复回归 |

H3 参考图模板保留原始模型和参数，默认将 137／139／147 三个 LoadImage 分别接入 ref_image_0／1／2；真正孤立的 LoadImage 不作为输入。更新 JSON 后按有效连线显示。首尾帧模板现使用用户补充的 MiniMaxH3_多参考图_已连接首尾帧_完整示例.json：参考图 137／139／152，首帧 147 → AddGuide 149（0），尾帧 148 → AddGuide 150（-1），最终引导条件接入 126；五张图片分别上传。该模板继续使用 ref2va 模型及已有采样分支，不切换为 fl2va。

自带副本只修正 CreateVideo.chroma_subsampling 的 none 为当前本地 ComfyUI 可接受的 auto，用户原文件未改。节点预检补充 optional 与新 COMBO.options 枚举，避免此类配置到远程提交时才被拒绝。用户已有保存配置不自动覆盖；MiniMaxH3ImageToVideo 独立首尾帧结构继续支持。

公开参数包括模板中的时长、种子、像素量、采样步数及参考图加速开关；不单独修改帧率，保留时长计算与模型网格关系。后端只修改本轮 JSON 副本。任务快照保留 workflow_id／name、各输入图片与参数，查询历史任务继续使用原始快照。

旧单工作流路径读取后转换为 JSON 快照，读取时丢弃未使用的 image_workflow 字段；旧单图任务仍可查询取回。后续资产生图完成文件仍通过 MediaRepository.import_image(path, source=...) 进入媒体库，本轮不提前实现生图。

### 开发验证

开发后清理：删除无生产调用的单工作流加载包装与常量、未使用的图片工作流配置字段；UI 每个图片输入直接导入单张图片，不保留旧批量导入后仅取末张的逻辑。保留已有项目和任务需要的读取兼容。

23 项专项覆盖粘贴新增与更新、保存重开、三图变四图、首尾帧角色、全部图片分别上传、类型参数、大整数种子、原配置不被生成修改、任务刷新、跨工作流结果隔离、提交丢失对账与下载恢复。全量 **241 passed（13.26 秒）**；相关短视频代码 Ruff 检查及格式、依赖、Markdown 链接与差异检查通过。

先前通过真实 UI 控件提交本地 ComfyUI 0.44.2，三次均成功生成、保存 MP4，Qt 各解码 20 帧、读取 5166 ms，未出现播放错误：

#### 首尾帧 5 秒复测（2026-11-15）

此次使用原工作流的三张食物参考图，首帧使用原桌面食物球图；由于原 JSON 尾帧仍是占位名，尾帧暂以第 3 张面碗参考图代测。两次均为 5 秒目标、0.1 百万像素、同一提示词和种子，保留原 VAEDecode，不重启 ComfyUI、不修改应用代码或默认工作流。

| 模式 | 总耗时 | 文件与播放 | 首帧效果 |
|---|---|---|---|
| 4 步加速 LoRA | 396.28 秒 | 416×256、24 fps、124 帧、约 5.17 秒，音频可解码，Qt 播放无错误 | 未保留指定桌面背景，更接近第 1 张参考图的黑底食物球 |
| 常规 20 步，关闭加速 LoRA | 255.72 秒 | 同上 | 第一帧近黑，未保留指定桌面构图 |

两次尾帧均呈现指定面碗的裁切近景。已对比服务器上传文件与 UI 所选图片的 SHA-256，并核对完整执行图和 0／-1 引导连接；首尾图片没有传错位置。每个视频完整解码出 124 个视频帧和 162 个音频帧，Qt 各播放解码 30 帧。加速测试的连续采样记录显存最高 23656 MiB，采样在运行中途启动，不代表完整运行峰值。两次耗时包含不同缓存状态，不用于直接比较模式性能。

结论：5 秒生成、保存与播放链路通过；**严格首帧控制效果未通过**。仍需检查工作流／模型的首帧引导效果，不能把服务器任务成功或图片上传正确等同于首尾画面验收通过。查阅本地 H3 VAE 实现发现它内部已切块，decode_tiled 忽略额外切块参数，因此此次未替换解码节点。

输出视频、抽帧、GPU 采样及 validation_report.json 保留在 quality_runs/comfyui_first_last_retest_20261115/ 供查看；临时脚本和独立测试项目输入副本清理到回收站。用户源文件与现有项目未修改。

四图实测发现并修复了预检把模板旧图片名与服务器现有文件列表比较的问题：LoadImage.image 会在上传后替换，预检只跳过这个临时文件枚举；模型等枚举照常校验。

历史 2026-11-14 单图验证：用户风雪图片生成 992×416、24 fps、124 帧的 MP4，约 341 秒；Qt 解码正常。当时 13 项专项与全量 231 项通过，只代表当日实现。

## 短视频内容分镜 Skill 与 MiniMax H3（2026-11-15）

现行 Skill 改名为 `short-video-content-storyboard`，中文标题“短视频内容分镜 Skill”，替换前一版趣味主导规则，收敛为拆镜、时长、衔接和输出检查四部分。常规单镜5–8秒，必要短镜低于5秒，超过8秒优先拆镜；重点控制单镜动作、运镜与生成复杂度，保持起止状态和跨镜声音连续。总时长仍少于60秒，有效目标逐镜闭合，内容风格由素材与用户决定。

核对 [MiniMax H3 官方模型卡](https://huggingface.co/MiniMaxAI/MiniMax-H3) 输出范围4–15秒及[官方提示词指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)的连续运动、首尾帧和6／8秒单镜示例。5–8秒是用户指定的本项目策略，不是官方稳定性最佳区间。低于实际工作流范围的短镜需后续裁切，计划时长不保证等于文件时长；未新增裁切、拼接或参数映射功能。

同步加载器、打包路径、阶段提示和分镜审阅要求。默认项目参考区间仍为旧值，不迁移用户配置，Skill 明确使用本任务策略；代码仍只保证正时长、时间轴与引用合法，不硬拦总时长。下述前一版记录仅为历史，不再代表现行规则。

验证：新 Skill 格式、代码语法、打包资源路径和文档链接通过；全量247项通过（14.31秒），包含 Skill 冻结加载、反馈修订和合理短镜保留。未调用真实模型或生成视频，未构建安装包；测试通过不等于已验证5–8秒片段的画面稳定性。

## 当前代码维护：兼容写法与编码风格

1. 使用满足当前需求的简单实现；在界面、领域、网络、存储和状态生命周期边界抽象，不为假设需求建立框架或隐式注册机制。
2. 变量表达具体业务对象；函数使用动词与业务对象；类表达明确职责；文件按业务功能命名。子任务有独立业务含义、需要复用或职责混杂时才拆分，避免机械拆分和多层转发。
3. 函数按必要校验、业务处理、返回结果组织。外部数据在进入业务前验证，内部调用遵循类型契约，不重复防御性兜底。
4. 参数和返回值写明类型；共享复杂结构使用明确契约。阶段不同的 JSON 内容通过 JsonObject 表达，并由对应阶段校验器检查，不能用该类型逃避必要的边界校验。
5. 明确单位与缺失语义：时间轴和时长为毫秒整数，原文坐标为 Unicode 码点，未指定目标使用 None，不用空字典或零值掩盖失败。
6. 当前层没有明确处理职责就让异常传播；只为恢复、维护失败状态、必要的接口转换或任务边界反馈而捕获。优先具体异常，原样重抛用裸 raise，转换用 raise NewError(...) from exc；任务边界记录完整错误，界面显示类型和消息。配置缺失首次使用明确报错，程序错误不重试、不返回默认结果。媒体提交、查询和下载的重试边界见接口设计第 10 节。
7. 保持入口、实际实现和中间结果可查；记录必要失败上下文，避免重复日志。网络替换通过显式 transport，文件与模型边界可独立验证。

仓库 ruff.toml 只覆盖当前短视频领域、界面和文字评估入口，检查名称／导入及函数类型标注，统一100字符排版。Ruff仅作为开发检查工具，不加入运行依赖；可运行 ruff check 和 ruff format --check。
