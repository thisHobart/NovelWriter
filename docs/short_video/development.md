## ComfyUI MCP 图生视频（2026-11-14）

本轮实现 UI 导图、内置 MCP 连接本地 ComfyUI、运行单图视频工作流、下载与播放。资产生图只保留配置和完成图片的接入接口，不执行图片工作流。无需先生成文章、分镜或完整提示词。

### 当前文件与职责

| core/short_video/v2/comfy_mcp.py | 官方 MCP SDK 2.x 内置客户端／服务端，上传、提交、查询、对账与下载工具 |

原工作流副本保存在 core/short_video/v2/workflows/minimax_h3_reference.json，原始用户文件不改动。实际输入为 137.image、138.value，输出为 92；未接入视频输出的 139、147 等节点不提交。默认模板仍保留原 10 秒、完整采样等参数；UI 使用可见的单图默认提示词，避免模板内三图文字与实际单图连线冲突。

图片文件通过 MediaRepository.import_image(path, source=...) 统一进入媒体库。后续图片工作流只需把取回的完整文件交给此入口；本轮不增加空壳生成方法或外部 MCP 服务部署要求。

### 已验证内容

专项覆盖图片实际上传与节点取值、视频下载、同请求重放、提交响应丢失后对账、下载失败后重取、停止不调用全局中断、内部 TypeError 原样传播、模型缺失预检、图片变化／错误参考图引用，以及无分镜时的 UI 导图生成。

使用用户提供风雪图片，在本地 ComfyUI 0.44.2 真实生成并保存一个 MP4：992×416、24 fps、124 帧，实际约 5.17 秒。测试副本改为 5 秒目标与原工作流自带的 4 步加速分支，耗时约 341 秒；原始 JSON、默认模板参数与用户现有项目未修改。结果另存于 quality_runs/comfyui_video_20261114/，Qt 播放读取到 5166 ms 且无播放错误。该验证证明链路可用，不代表所有提示词的画面效果或其他工作流也已验证。

新增 13 项专项回归，全量 **231 passed（14.23 秒）**；相关代码 Ruff 检查与格式检查、依赖完整性、文档链接及差异检查通过。Qt 播放实际解码 57 帧，未出现播放错误。完整记录见根目录 DEVLOG；此前各节用例数只代表当时结果。未构建新的桌面安装包。

### 使用与后续边界

进入“提示词 → 镜头”导入图片，修改视频文字后点击生成；顶部“服务配置 → ComfyUI 工作流”可更换地址和已适配的工作流 JSON。生成期间沿用单任务调度，停止后需自行点击查询原任务；软件不重发未知 GPU 工作，不增加预算限制。

多图共同参考、首尾帧、其他模型的节点、资产生图执行、自动合成分镜画面、批量队列和成片剪辑均未实现；新增时按实际工作流扩展明确映射，不建立通用节点编辑框架。

## 镜头提示词缺失时的展示（2026-11-11）

资产任务中断时可能已保存部分资产但没有 prompt_bundle。PromptPage 按当前分镜展示逐镜画面草稿，支持复制并提示缺少的资产数量；仅当完整结果关联当前分镜时恢复编辑。草稿只在内存中转换为展示内容，查看不写项目、不调用模型；生成按钮复用现有资产任务。新增三项 Qt 回归，覆盖缺失资产时逐镜查看与复制、生成入口、完整结果到达后编辑保存、旧分镜结果隔离。当前项目只读核对：7 个镜头均可显示草稿，缺少 5 项资产，项目清单未改变。

当前全量 **151 passed（10.22 秒）**。已核对实际项目的离线界面显示；未请求模型补齐缺失资产，未改用户项目内容。

## 当前实现与入口

清理无调用方的独立检查服务、人工确认和报告写入接口、旧资产模板编译、单独视图优化及视频运动文字生成分支。资产设定及全部视图统一走 asset_spec；镜头仍本地编排并通过 shot_prompts 优化。同步删除旧通用编辑器只读字段表、未使用的已保存记录访问器与页面状态。存储保留已有 confirmations／reports 和历史运行清理所需的读取逻辑，不修改用户项目。测试夹具使用完整视图样本和实际 finalize_asset_prompts，不再依赖已移除的生产模板函数。

清理后全量 **151 passed（10.42 秒）**。额外离线集成验证当前镜头优化、未选镜头不变与资产引用保留；现有项目 80 条记录读取正常、清单不变。语法、文档引用和差异检查通过；未调用真实模型。

- `storyboard_skill.load_storyboard_skill` 读取 [SKILL.md](../../core/short_video/v2/skills/short-video-storyboard/SKILL.md)，在 storyboard 的 prepare 阶段追加到 instruction；requirements 与 prompt 冻结同一份 Skill，后续检查和重试不重新读文件。只在分镜生成时加载，不向普通聊天或资产阶段注入。打包配置包含该资源；文件缺失直接暴露读取错误，不静默降级为旧提示词。
- 分镜专用审阅检查机械均分、声画时长、隐藏切镜、重复旁白、文案覆盖和连续性。`local_issues` 使用实际配置区间；超出区间及四镜以上全部同长只作为待核对线索，由 AI 结合具体内容判断。手动保存不要求解释例外、不自动拉伸时长。仍复用默认两次质量重试，不增加检查 UI。
- `workflow.py` 的 `WorkflowService.execute` 负责准备输入、生成、接收反馈和控制重试。`DEFAULT_MAX_RETRIES=2`；prepare 冻结该值，0 表示首次生成并检查后结束。通过提前停止；持续不通过输出最新候选，保存 review_status=issues 状态而非通过状态，不按问题数选择较早内容。
- `review.py` 的 `check_candidate` 接收阶段要求、必要上下文与当前候选，复用现有规则和检查响应校验，返回 `QualityCheckResult(passed,feedback)`。它不触发生成，不保存报告。重试输入保留原始任务、上下文并加入最新候选与反馈。
- `prompts.py` 的 asset_spec 一次要求模型生成基础设定和完整 views；人物、场景、道具有各自的视角与可见性要求。`validation.validate_generated_asset_prompts` 校验新模型输出的具体字段及计划视图；`prompt_compiler.finalize_asset_prompts` 仅规范顺序和内部指纹，保留模型文字。旧模板编译和单独视图优化分支已删除；手动保存和历史读取沿用原契约。
- 资产审阅对照基础设定检查整组视图，分类型检查人物朝向、场景布局和道具可见表面，反馈包含具体路径、矛盾及建议。只检查文字，不声称验证了图片；反馈修订继续使用原有质量重试流程。
- 反馈、问题及检查原文只在本轮内存中使用，不保存检查报告或持久化 issues。已删除无调用方的独立检查服务与人工确认、报告写入接口。阶段 calls 仅记调用类型、错误类型和时间，调用计数回调不传原文。初始命令仍保存任务上下文；聊天和分段调用有独立的原文记录，不能套用阶段 calls 的限制。
- `creation.py` 接通目录／分镜与人物、场景、道具提示词；`batches.py` 的最终合稿复用相同 Agent Loop。镜头提示词重新生成仍使用该流程。普通讨论不进入质量检查，不新增图片／视频能力或检查 UI。
- 已删除 RequestBudget、BudgetExhausted、总请求次数／总时长检查和 120 秒墙钟期限；网络超时由 SDK 管理。质量修复与格式修复分别有限重试，互不占用次数。请求数和耗时仅用于记录；接口／检查异常不当作质量反馈，取消和内部错误沿用既有处理。
- 编辑区未新增控件，只显示简短的未通过／未完成状态，最新候选可直接手改并保存。

合法候选在检查前落盘并添加到运行 output_refs，暂不切换 current。收尾核对 selection_snapshot 和 selected_before；当前内容已被其他操作修改时返回 selected=false，仅保留历史候选。已有候选时，服务或可处理的输出异常返回 unavailable；取消和其他异常停止并保留已落盘内容。运行 succeeded 不等于 review_status=passed。历史 incomplete 状态仍可显示。

## 当前代码维护：兼容写法与编码风格

1. 使用满足当前需求的简单实现；在界面、领域、网络、存储和状态生命周期边界抽象，不为假设需求建立框架或隐式注册机制。
2. 变量表达具体业务对象；函数使用动词与业务对象；类表达明确职责；文件按业务功能命名。子任务有独立业务含义、需要复用或职责混杂时才拆分，避免机械拆分和多层转发。
3. 函数按必要校验、业务处理、返回结果组织。外部数据在进入业务前验证，内部调用遵循类型契约，不重复防御性兜底。
4. 参数和返回值写明类型；共享复杂结构使用明确契约。阶段不同的 JSON 内容通过 JsonObject 表达，并由对应阶段校验器检查，不能用该类型逃避必要的边界校验。
5. 明确单位与缺失语义：时间轴和时长为毫秒整数，原文坐标为 Unicode 码点，未指定目标使用 None，不用空字典或零值掩盖失败。
6. 当前层没有明确处理职责就让异常传播；只为恢复、维护失败状态、必要的接口转换或任务边界反馈而捕获。优先具体异常，原样重抛用裸 raise，转换用 raise NewError(...) from exc；任务边界记录完整错误，界面显示类型和消息。配置缺失首次使用明确报错，程序错误不重试、不返回默认结果。媒体提交、查询和下载的重试边界见接口设计第 10 节。
7. 保持入口、实际实现和中间结果可查；记录必要失败上下文，避免重复日志。网络替换通过显式 transport，文件与模型边界可独立验证。

仓库 ruff.toml 只覆盖当前短视频领域、界面和文字评估入口，检查名称／导入及函数类型标注，统一100字符排版。Ruff仅作为开发检查工具，不加入运行依赖；可运行 ruff check 和 ruff format --check。

## 模型配置、对话与编辑

短视频顶部和项目设置均复用第一部分 ModelConfigDialog；两部分共享服务商、地址、密钥与模型，运行中禁用配置切换。普通聊天只提供建议，不恢复作用目标、应用修改、聊天修订或另存候选。稿件与提示词直接编辑保存；仅文案与分镜支持历史恢复。人物／场景／道具及镜头提示词按对象与状态保留当前一份，替换时清理旧记录和中间候选，取消提示词旧来源提示及确认。打开项目的恢复步骤清理已有非当前提示词，普通读取保持只读。

聊天入口统一使用 ConversationStore 和 build_conversation_context。ConversationService 中重复的文件读写与上下文拼接已删除；界面和评估入口直接访问 service.store。长历史按完整轮次裁剪副本，本轮消息只加入一次。预检失败不落盘，执行时保存用户消息与最终回复，停止和恢复沿用明确终态。详见[会话管理](conversation_management.md)。
