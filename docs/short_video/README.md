# 第二部分：网文视频推广工作台

文档版本：2.5；更新日期：2026-11-04。四工作区、生成 Agent Loop 与独立纯聊天已实现；分镜新增整段文本复制，文件导出仅保留 Markdown。文档修订不改变项目数据 schema；历史验证记录及复验方法见开发文档。

目标流程：原文 → 小说推文 → 视频推广文案 → 分镜 → 人物／场景／道具提示词 → 导出。
界面保留原文、改写、分镜、提示词四工作区和左侧共享对话，导出为统一按钮。
分镜页“复制分镜文本”输出视觉风格、场景概述、逐镜时间段、镜头要求、音频和限制，可直接整段粘贴。Markdown 导出使用此段落结构；格式示例见[交互设计](interaction.md#5-p-03-分镜)。
Agent Loop 默认首次生成后最多重试 2 次，检查仍未通过时输出最新候选供编辑；反馈不持久化。检查和有限修改在后台完成；左侧对话仅发送用户消息和聊天历史，已移除文档引用及说明；用户在右侧直接编辑并保存。不提供作用目标、应用修改、按意见修订或另存候选入口。

启动入口：项目虚拟环境运行 python main.py，首页切换到短视频脚本。顶部进入原文、改写、分镜、提示词，顶部“模型配置”与项目设置共用第一部分的配置窗口，导出为统一操作。
项目数据、文字服务、会话和导出能力继续复用；不接入图片或视频生成服务。文案与分镜保留历史版本；人物／场景／道具及镜头提示词仅保留当前一份，生成或保存时替换，取消提示词历史恢复和旧来源确认。不同对象、状态及视图仍分别保留。新流程不要求检查、确认或绑定操作。

阅读顺序：先看架构中的总时序，再看 Agent Loop 内部流程；聊天单独看会话管理时序。普通聊天不会附加项目文档、不进入质量循环；默认 48,000 字符容量超限时裁剪最早完整历史轮次的请求副本，保留本轮消息与磁盘历史。

当前默认预算：单阶段 6 次／300 秒，分镜组合 12 次／600 秒；资产按待生成项共享预算。格式修复、失败和 AI 检查均消耗预算。合法候选在检查前保存，检查不通过达到上限仍返回最新候选。初次资产视图及镜头提示词由代码编译，优化镜头提示词才调用模型。
