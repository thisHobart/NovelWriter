# 小说创作：交互设计

日期：2026-11-25。本文说明小说各页面的按钮和状态。
整体结构见[架构设计](architecture.md)，调用与文件见[接口设计](interfaces.md)。
配色、控件、主窗、状态栏和后台任务等两个功能共用的规则见[两个功能的边界 · 共用界面](../feature_boundaries.md#共用界面)。

## 1. 工作区

左侧步骤栏依次是「工作流总览」「作品参数」「世界设定」「故事结构」「场景规划」「章节撰写」，底部是「运行后端」「模型服务」和「配置」。

| 阶段状态 | 图标 | 副文案 | 可点击 |
|---|---|---|---|
| 已完成 | 对勾 | `已完成` 或完成说明 | 是 |
| 部分完成 | 半环 | 缺什么，例如 `还缺第 23、24 章正文` | 是 |
| 阻塞 | 锁 | 阻塞原因原文，常驻显示 | 否，点击时状态栏提示原因 |
| 未开始 | 虚线圆 | `未开始` | 是 |
| 运行中 | 转圈 | `进行中 · <当前子步骤>` | 是 |

状态以磁盘产物为准（见[架构设计](architecture.md#3-关键决定)）。小说只有一个后台任务通道，任务进度和「停止」都在底部状态栏。

## 2. 工作流总览

四个阶段各一张卡片，显示状态，可「单独运行」或「打开」。右栏：

| 控件 | 结果 |
|---|---|
| 运行完整流程 | 依次运行四个阶段 |
| 从断点继续 | 只运行未开始和部分完成的阶段；没有时提示「没有待继续的阶段。」 |
| 扫描已有成果 / 刷新 | 重新读取磁盘判定状态 |
| 分析当前内容 | 在状态栏显示各阶段文件数和正文累计字数，不调用模型 |
| 切换到短视频脚本 | 切到另一个功能 |

## 3. 作品参数

页面只有一张「核心信息」卡：输出目录、作品标题、题材、故事篇幅、主题、基调。

| 控件 | 结果 |
|---|---|
| 题材 | 可下拉选「悬疑推理」「恐怖」「科幻」「爱情」，也可直接改写，不能为空；下方提示列出评审规则认的关键词，都不含时用通用规则 |
| 主题 / 基调 | 可下拉选，也可直接改写；预设跟着题材换，见下文 |
| 故事篇幅 | 短篇小说 / 中篇小说 / 长篇小说；新作品换篇幅时分幕跟着换（短篇、中篇三幕，长篇六幕） |
| 浏览… | 选择输出目录；取消不改动 |
| 保存参数 | 校验后写入 `system/parameters.txt`；出错的字段逐个标红，状态栏汇总，不弹窗 |
| 加载参数 | 有未保存修改时先确认 |
| 任意字段变更 | 状态栏显示「参数已修改，尚未保存」；下游已有产物时追加提醒，不删除任何产物 |

**主题、基调的预设。** 从列表里选中题材，或写完题材离开输入框时，主题、基调的下拉列表换成这个题材的预设；框里空着或仍是某个预设项时换成新列表的第一项，自己写的内容保留。打字途中不换。自己写的题材按评审规则的关键词归到相近的预设，例如「都市悬疑」用悬疑推理的预设；都不沾时用一组通用预设。自己写的内容不加进下拉列表。可改写的下拉框右端有箭头，点它展开预设。

势力数量、人物数量按篇幅决定（见「世界设定」），质量闭环档位在「章节撰写」页选择，和作品参数一起保存。

打开旧版作品时，子题材并进题材框（如 `爱情（当代爱情）`），超出三档的篇幅换成长篇小说，已有的分幕结构不变；页面随即显示「参数已修改，尚未保存」，保存后旧格式里的作者姓名、性别比例和附加设置不再写回。

下拉框不响应鼠标滚轮。

### 生成前选择参数

界面有未保存修改、或界面与已保存参数不同时，任何生成入口先弹出选择：

| 选择 | 行为 |
|---|---|
| 保存并生成 | 校验并保存后启动；保存失败停在参数页，不调用模型 |
| 使用已保存参数 | 用磁盘版本运行，界面草稿保留；从未保存过参数时不可选 |
| 取消 | 不保存，不启动 |

模型服务不属于作品参数，始终用当前选择。

## 4. 世界设定

页面由页头、左侧（改动条、状态说明、产物页签）和右栏「分步生成」组成。会覆盖已有设定的操作都不弹确认，改完可以在改动条里撤回。会花模型请求的按钮，悬停都写约几次请求（每份产物生成 1 次、检查 1 次；人物背景一人一份；候选标题 1 次）。

**页头。** 副标题写「6 个势力 · 8 个人物」，还没有设定时写「世界构建与背景 · 尚未生成」。整页只有一个蓝色按钮，就在页头，写的是现在该做的那一件事，跟着状态说明走（见下表）。旁边可能有一个白色按钮：设定已经能用、但还有事要处理时是「下一步：故事结构」；整段生成停在一份已保存但有问题的结果上时是「就用现在的，继续生成」。生成进行中两个按钮都不可点，蓝色按钮显示「正在…」。

| 控件 | 结果 |
|---|---|
| 更多 → 重新生成世界设定 | 有任何设定后出现：按作品参数从势力开始重写全部设定，可撤回。缺项时想整段重来也从这里点，不占页头 |
| 更多 → 打开设定文件夹 / 打开生成记录 | 打开本作品的设定目录；生成记录是每次请求的提示词和检查报告原文，排查问题时用 |

**改动条。** 有改动后出现在左侧顶部：「最近一次改动：生成势力（14:32）」和「撤回」；撤回后多出「已撤回：生成势力」和「恢复」。可以连续撤回多步；撤回后再做新的改动，「恢复」就不再出现（旧版本仍留在磁盘）。记录的改动有：整段生成、单步生成（生成过的叫「重新生成…」，和右栏按钮同名）、让 AI 再修一次、再修一次并继续生成、接着生成后面几项、按新势力重写后面几项、就用现在的，继续生成、采用草稿、编辑保存、改名、全部标为已看过。生成进行中两个按钮不可点。撤回时，后面阶段在这段时间里改写过的文件会标为待核对。

**状态说明和页头按钮。** 改动条下面一句话说清设定现在怎样，一次只说一件事，不另放按钮；该做的事在页头。按下表从上往下取第一种成立的：

| 情形 | 状态说明示例 | 页头蓝色按钮 | 页头白色按钮 |
|---|---|---|---|
| 还没有设定 | 还没有世界设定。点「生成世界设定」，按作品参数一次写好势力、人物、世界观和人物背景；也可以在右侧分步生成。 | 生成世界设定：依次生成势力、人物、世界观、人物背景和候选标题（约 13 次请求） | — |
| 整段生成停在一份上 | 整段生成停在势力：有问题，已保存。 / 整段生成停在人物：没有采用，返回内容读不出来。 | 再修一次并继续生成：修好后接着把后面几步跑完 | 停在已保存但有问题的那份时：就用现在的，继续生成。读不出来时没有 |
| 有 1 份要处理 | 1 份需要处理：人物背景「陈放」（有问题，已保存）。 | 让 AI 再修一次 | 势力、人物、世界观都在时：下一步：故事结构 |
| 要处理的不止 1 份 | 2 份需要处理：…。 | 去处理（2 份）：打开「生成结果」 | 同上 |
| 有过期的 | 人物、世界观、人物背景是按旧势力写的。 | 按新势力重写后面几项（悬停：约 10 次请求，会重写哪几项，可撤回） | 下一步：故事结构 |
| 还差几项 | 还差世界观、人物背景。 | 接着生成后面几项（悬停：依次生成哪几项、约几次请求） | — |
| 已就绪 | 世界设定已就绪：6 个势力 · 8 个人物 · 世界观 · 3 份人物背景。有 2 条检查备注，在「生成结果」里。 | 下一步：故事结构 | — |

同一份连续两次修过仍有问题时，状态说明多一句「检查可能判严了，内容可以用就点「就用现在的，继续生成」。」

过期只看世界设定内部的生成先后：势力比人物新，人物、世界观和人物背景就算按旧势力写的。撤回的那次生成不算，手动编辑不算；旧作品没有生成记录时不判断。

**产物页签。** 没有设定时左侧只有状态说明。有了以后只显示有内容的页签：

| 页签 | 内容和按钮 |
|---|---|
| 世界观 | 正文；「编辑」 |
| 势力 N / 人物 N | 卡片；人物卡角标写身份（主角、第二主角、反派、配角）。每张卡「编辑」，有人物背景的另有「编辑人物背景」 |
| 名称与规则 | 年代、技术水平、世界规则和名称登记；「编辑」 |
| 人物关系 | 每对人物一行；「编辑」 |
| 候选标题 | 每个标题旁「用作作品标题」：填进作品参数并保存，状态栏写明原标题；作品参数页还有别的未保存修改时只填入、不替作者保存。底部「换一组」（1 次模型调用） |
| 待核对 | 有事项时出现，见下文 |
| 生成结果 | 有生成记录时出现，见下文 |

文字页签打开时从第一行显示。已经不属于现有人物的旧背景文件（人物改名、换身份或整批重生成后留下的）不列出，也不写进后面阶段的提示词；文件仍在设定文件夹里。

**右栏 · 分步生成。** 卡片角标「N / 4 已完成」，下面一行「按篇幅（长篇小说）生成 6 个势力 · 8 个人物」：说的是生成时写几个，数量由篇幅决定，短篇 3 / 5，中篇 4 / 6，长篇 6 / 8，不让作者填。四个按钮：没生成过的叫「生成势力」「生成人物」「生成世界观」「生成人物背景」；生成过的叫「重新生成势力」等，带完成标记和数量，如 `✓ 重新生成势力  6 个`。悬停写清后果，例如「替换现有 6 个势力（约 2 次请求）。之后人物、世界观、人物背景会标为按旧势力写的。可撤回。」人物背景的悬停写「给主角、第二主角、反派各写一份详细背景」，需先有人物。要处理的事不挂在这些按钮上，只在状态说明和页头里。

**生成结果。** 每份产物最多初次生成加两次自动修复。检查只说「信息不足、判断不了」时照样交付，检查意见作为「检查备注」显示，不算待处理，状态栏写「任务已完成 · 有 N 条检查备注」。规则没通过仍保存可读结果；只有完全没取得内容才算任务失败。

**整段生成在哪里停。** 一份结果没能采用（只留了草稿）时停；势力、人物、世界观三项里任何一项自动修过仍有问题时也停，因为后面几项都按它写。人物背景、候选标题有问题不停，后面没有东西依赖它们。停下时记下还剩哪几步，页头给「再修一次并继续生成」；停在已保存但有问题的那份上时，还可以「就用现在的，继续生成」：这份不再算要处理（卡上写「有问题，就用现在的」，问题照旧列着），剩下几步按它接着写。工作流总览的「运行完整流程」也在这里停，状态栏写「世界设定停在半路，处理后可继续后续阶段」，不会拿缺了世界观的设定去写故事结构。

「生成结果」页每份产物只摆最新一张卡，更早的几次收在卡底「更早的记录（N）」。悬停卡片可看请求次数、修复次数和用时。保存了但有问题的那份在卡上列出问题；没有采用的那份只写「当前设定没有被替换；返回的原文保留着……」，读取报错原文放在悬停提示里。

卡上的按钮都是白色，蓝色只留给页头那一个。

| 卡片状态 | 按钮 |
|---|---|
| 已完成 / 已完成 · 有检查备注 | 无 |
| 有问题，已保存 / 已保存，检查没做完 | 让 AI 再修一次、编辑。整段生成停在这份时是「再修一次并继续生成」「就用现在的，继续生成」「编辑」 |
| 有问题，就用现在的 | 无 |
| 没有采用：返回内容读不出来（或已停止、生成期间设定被改过、保存失败、上次运行中断） | 让 AI 再修一次、编辑原文。整段生成停在这份时是「再修一次并继续生成」：修好后接着把后面几步跑完 |
| 草稿已保存，还没采用 | 让 AI 再修一次、编辑原文 |
| 没有取得内容 | 让 AI 再修一次 |
| 已手动修改 | 无：保存后作者改过这份内容；撤回那次编辑会回到原来的状态 |
| 已撤回 | 无 |

「编辑原文」打开原始返回，可保存草稿，或改成能读的内容后采用为当前设定；不调用模型。生成结束后留在原来的页签，只有需要处理时才切到「生成结果」。步骤栏「世界设定」有待处理时追加「· N 份待处理」。

**编辑与改名。** 编辑窗口绑定打开时的项目快照，关闭时可保存、放弃或取消；后台生成期间不能提交；文件被外部改过时不覆盖。人物、势力、地点改名会同步结构化引用（关系两端、所属势力、登记表、背景文件名），并把世界设定里正文、人物背景、人物和势力描述、登记表中的完整旧名一起换成新名；几个改名一遍同时换，不会连环替换。旧名只有一个字、或是别的名字的一部分时不换，留在待核对里。编辑窗口「预览 / 影响范围」写明「保存后会把世界设定里 5 处「苏桐琳」改成「苏桐」」，以及「故事结构 8 个文件、场景规划 1 个文件里还写着「苏桐琳」或它的别名，不会自动改，保存后列在「待核对」里。」下面列出的文件写中文名，如「故事结构 · 结局」「第 3 章场景」「第 12 章正文」。当前不支持新增或删除人物、势力和关系。

**待核对。** 有事项时才出现，按阶段汇总成几行。每行可「查看文件」，后面阶段的行带「去故事结构」这类跳转。「全部标为已看过」清空列表，可以撤回；之后再改设定会重新列出。后面阶段列哪些文件，看这次保存改了什么：

| 这次保存 | 待核对 |
|---|---|
| 只改了名字（加上系统跟着做的替换） | 世界设定里能换的已经换了，不再写「请核对……是否一致」；只列没换掉的地方。后面阶段只列还写着旧名或别名的文件，按名字和登记过的别名查找（一个字的别名、新名里也有的别名不查），例如「故事结构：8 个文件仍写着旧名「苏桐琳」（现名「苏桐」）。」预览写「后面几个阶段按名字和别名查找；没写到这些名字的文件不用核对。」之前没核对完的事照旧留着 |
| 还改了别的内容，或重新生成 | 顶上一句「设定已修改，请核对正文、人物背景与名称及规则登记表是否一致。」（生成后是「设定已重新生成，请核对相关内容。」）；后面阶段的文件全部列出，例如「故事结构：10 个文件是按旧设定写的，其中 8 个仍写着旧名「苏桐琳」（现名「苏桐」）。」。预览写「这次除了名字还改了别的内容，后面几个阶段的文件都会列进「待核对」。」 |

后面阶段的页面顶部只在那个阶段有待核对的文件时出现「设定已修改，待核对」横幅。

## 5. 故事结构

| 控件 | 结果 |
|---|---|
| 生成故事结构 | 依次生成人物弧光、势力弧光、融入地点、详细情节 |
| 生成人物弧光 / 生成势力弧光 / 将地点融入故事弧 / 创建详细情节 | 单步生成 |
| 幕卡片 | 展开该幕全文 |

幕卡片按所选结构里的先后排，标题用中文名，例如六幕式依次是「开端」「情节上升」「第一次高潮」「寻找解决方案」「第二次高潮」「结局」；门禁和场景规划的阻塞原因用同样的名字。

右栏「门禁」逐条列出下一阶段被阻塞的原因。

## 6. 场景规划

| 控件 | 结果 |
|---|---|
| 规划场景 | 生成章节大纲，再逐章规划场景 |
| 生成章节大纲 / 规划场景 | 单步生成 |

故事结构未通过时显示阻塞空态：标题说明缺什么，正文列出具体缺口，主按钮「前往故事结构」，另有「忽略门禁，强制规划」。强制规划不删除已有产物，生成的场景不标记为通过，阶段保持部分完成。

「输入依赖」面板说明门禁读的是磁盘产物，手动改文件后需要刷新。已验收章节的场景规划不再重新生成。

## 7. 章节撰写

| 控件 | 结果 |
|---|---|
| 撰写下一章 | 写第一个未写的章节；状态栏显示 `第 N 章 · 场景 i/j` 和停止 |
| 撰写全部剩余章节 | 连续写到最后；每章验收后立即保存；遇到被拦下的章节整轮停止 |
| 重写本章 | 已有正文时先确认 |
| 分析章节 | 只读分析，结果显示在右栏 |
| 章节列表 | 切换正文；生成中也可切换 |
| 停止 | 已保存的场景保留，未完成的章节标为部分完成 |
| 质量闭环 · 档位 | 关闭 / 标准 / 严格，下方一句话说明代价；改动算作品参数修改，和其他参数一起保存，只影响之后写的章节 |

### 待复审

质量闸门拦下一章时，这一稿不进正式稿件，章节进入待复审：

| 位置 | 表现 |
|---|---|
| 章节列表 | 单列「待复审」，右侧写 `N 处硬伤` / `N 项未达标`；评审没给出结论时写 `评审未出结论` |
| 页头副标题 | `第 N 章待复审 · 已完成 M 章 · X 字` |
| 正文区 | 显示被拦下的这一稿，顶部横幅说明不在正式稿件里；被点名的句子标底色 |
| 右栏「复审」卡 | 卡在哪个评审、差多少分；问题按 硬伤 → 未达标维度 → 可选润色 排序，点一条滚到正文位置 |

| 控件 | 结果 |
|---|---|
| 照建议重修 | 只带勾选的条目重修，条目按引文分到所在场次；全部没勾时拒绝执行；仍不过则刷新清单 |
| 重跑评审 | 评审未出结论时替代「照建议重修」；只重判，不改正文 |
| 人工放行 | 先问理由；放行后验收照跑，理由记入账本 |
| 回去改规划 | 跳到场景规划 |

- 只写到一半就被拦下的章节没有完整正文，「照建议重修」和「人工放行」都不可用，只能「重写本章」。
- 问题出在场景规划本身时，复审卡注明规划里哪一句要改；勾选的条目全是规划问题时，「照建议重修」拒绝执行并说明去哪改。
