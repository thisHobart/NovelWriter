# 世界设定编辑

AI 生成完成后，可在「世界设定」中手动修改已有内容，保存不调用模型。

生成前的参数选择、禁用元素、符合性检查和报告查看见[生成参数一致性](parameter_consistency.md)。

## 使用

- 世界观页点「编辑」，修改 Markdown，并在「预览 / 影响范围」查看效果。
- 人物、势力卡片点「查看 / 编辑」，修改名称、属性及已有嵌套字段。
- 人物卡片提供已关联的详细背景入口；「人物背景」页按文件名列出全部背景，包括旧项目未关联文件。
- 「名称与规则」编辑年代、技术水平、世界规则和规范名称，登记 ID 保持不变。
- 「人物关系」编辑已有关系。当前版本不支持新增或删除人物、势力和关系条目。

关闭编辑窗口时可以保存、放弃或取消。刷新不会覆盖打开的草稿；后台生成期间不能提交编辑。
若保存失败，编辑窗口保留草稿并显示原因。文件被外部程序修改时不会强行覆盖；请保留草稿，重新打开核对。

## 改名与核对

人物改名同步关系两端、反派目标引用、名称登记及可明确关联的背景文件名；势力改名同步所属势力和冲突引用。
登记映射不能唯一确定时，保存会要求选择对应条目。没有可选条目的旧登记表需先修复，或保留原名继续编辑属性。

自由文本不会自动全文替换。残留旧名和一致性提醒显示在「待核对」页。已有大纲、场景和正文保留，仍可继续生成。
请完成核对后点「已核对当前版本」；新的设定修改会再次提示。局部重新生成只清除实际重写文件的下游提示。
提示仅表示需要人工核对，并不代表系统已经完成语义一致性验证。

后续生成读取保存后的正文、卡片、背景和名称规则表。名称、年代与技术规则以登记表为准，人物及势力属性以卡片为准；请同时修正自由文本中的冲突。

## 保存与备份

原有文件格式和未知字段保留。人工保存只做数据与引用校验，不强制 AI 生成的性别比例和中文措辞偏好。
新旧人物字段和数组形式保持原样；旧数据已有的引用缺陷不阻止无关修改，新引入的引用缺陷会阻止保存。

- `system/lore_edits.json`：设定版本、指纹、人工修改文件及待核对记录。
- `system/lore_history/<记录 ID>/transaction.json`：保存前的原始文件字节（Base64）及事务状态。写入失败回滚，未完成事务在下次访问时恢复。
- `system/lore_history/<记录 ID>/backup.json`：重新生成前的设定文本备份。
- `system/.lore.lock`：手动保存与标准阶段生成共用的跨进程锁。

备份不放在生成输入目录，不自动删除。本期没有历史版本恢复界面；需要恢复时可从备份提取文件。
不要在生成运行期间用外部编辑器修改项目。应用自己的保存和标准生成入口共享锁，外部编辑器不遵守该锁。

## 开发接口

`LoreRepository.load_snapshot()` 返回绑定项目及文件指纹的快照；`preview(snapshot, edits, mappings)` 返回关联更新与影响；
`save(snapshot, edits, mappings)` 校验、备份并提交。`edits` 的键为已有设定文件的项目相对路径，值为完整文本。
界面使用类型表单修改原始对象，未知字段不丢弃。`MappingRequired` 携带待选择的登记条目。

`tracked_generation` 包装标准阶段入口，执行前备份设定，并用实际输出文件的内容和修改时间识别被重写的文件。
失败任务保留已生成内容和待核对提示。`lore_context()` 提供最新设定上下文与完整指纹，事实基线据此判断是否需要刷新。
