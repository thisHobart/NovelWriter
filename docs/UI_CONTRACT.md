# UI 交互契约（PySide6 重构）

设计画布定义"长什么样"，本文件定义"怎么动"。写 PySide6 时以本文件为规格；
两者冲突时以本文件为准，并回头修画布。

状态枚举沿用 `core/generation/workflow_status.py` 的 `BLOCKED / PARTIAL / COMPLETE`。

## 0. 设计 token

| token | 值 | 用途 |
|---|---|---|
| `ink.900` | `#1C1B19` | 主文字 |
| `ink.600` | `#6E6C67` | 次要文字、标签 |
| `ink.400` | `#9A9792` | 三级文字、禁用 |
| `line` | `#E4E4E1` | 分隔线、卡片边框 |
| `line.strong` | `#D6D5D1` | 次要按钮边框 |
| `rail` | `#F4F3F0` | 左侧栏底色 |
| `canvas` | `#FFFFFF` | 卡片/编辑区底色 |
| `surface` | `#FAFAF8` | 内容区底色、状态栏 |
| `accent` | `#2C4A7C` | 主按钮、当前步骤、生成中 |
| `accent.tint` | `#EDF1F8` | 聚焦光晕、选中行 |
| `success / warn / danger` | `#2F7D4F` / `#B4761D` / `#B3392F` | 语义 |

间距只用 4 的倍数；字号只用 11 / 12 / 13 / 16 / 19；控件高 32px；圆角 4px（卡片 6px）。
字体：界面 `Noto Sans SC`（回退 `PingFang SC` / `Microsoft YaHei`）；
标题与正文稿 `Source Serif 4`（回退 `Songti SC` / Georgia）。

强调色只允许出现在：主按钮、当前步骤指示条、生成中徽标与进度条。一屏不超过 3 处。

## 1. 主窗壳

| 区域 | 尺寸 | 说明 |
|---|---|---|
| 左侧步骤栏 | 固定 248px | 不可折叠（后续可加） |
| 内容区 | 自适应 | 顶部 64px 页头 + 主体 + 底部 44px 状态栏 |
| 最小窗口 | 1200 × 760 | 低于此值内容区横向滚动，不重排 |

### 1.1 步骤栏行状态

| 阶段状态 | 图标 | 副文案 | 可点击 |
|---|---|---|---|
| `COMPLETE` | 对勾（success） | `已完成 · N 个文件` | 是 |
| `PARTIAL` | 半环（warn） | `部分完成 M/N` | 是 |
| `BLOCKED` | 锁（ink.400） | 阻塞原因原文（`StageStatus.detail`） | 否，点击时状态栏提示原因 |
| 未开始且未阻塞 | 虚线圆（ink.400） | `未开始` | 是 |
| 运行中 | 转圈（accent） | `进行中 · <当前子步骤>` | 是 |

当前阶段：白底 + 1px 边框 + 左侧 2px accent 竖条 + 标题 600 字重。

阻塞原因必须常驻在步骤栏，不得只在弹窗里出现（现有实现的问题）。

### 1.2 底部状态栏

单一后台任务通道。同一时刻只显示一个任务。

| 状态 | 内容 |
|---|---|
| 空闲 | 灰点 + `空闲`｜输出目录｜右侧 `上次保存 HH:MM` |
| 运行中 | 转圈 + `正在<动作> · <子进度>` + 进度条(200×5) + 已用时 + 右侧红色 `停止` |
| 参数脏 | warn 半环 + `参数已修改，尚未保存` + 一致性提示 |
| 失败 | danger + 错误摘要 + `查看日志` 链接（点击打开日志文件） |

`停止` 只在任务运行时出现，绑定 `CancelToken.cancel()`；点击后立即变为
`正在停止…` 并禁用，直到 worker 抛 `GenerationCancelled`。

## 2. 后台任务契约（替换 task_runner.py）

Tk 的 `root.after` 轮询改为 `QThread` + 信号。调用方约定不变：

| 旧参数 | 新形态 |
|---|---|
| `busy_widgets` | `TaskRunner.run(..., disable=[w1, w2])` |
| `busy_button` + `busy_text` | 按钮进入 `busy` 态：自身禁用、文案换为 `busy_text`、左侧加转圈图标 |
| `cancel_button` | 不再由调用方传入；统一由状态栏的 `停止` 承担 |
| `on_success / on_error / on_done` | 信号 `succeeded(object)` / `failed(Exception)` / `finished()`，均在主线程 |
| `on_cancelled` | 信号 `cancelled()` |

worker 线程**禁止**触碰任何 QWidget。进度上报走 `progress(str, float)` 信号。

## 4. 阶段 1 · 作品参数

字段来源：`core/config/story_options.py` 与 `core/gui/pages/parameters_page.py`。

| 控件 | 触发 | 结果 |
|---|---|---|
| 题材下拉 | 变更 | 重新填充子题材；子题材重置为首项；触发 4.1 |
| 子题材下拉 | 变更 | 重建右侧动态页签（原 `update_dynamic_tabs`）；已填未保存的动态字段清空前弹确认 |
| 故事篇幅 | 变更 | 解锁并填充「故事结构」下拉 |
| 质量闭环 | 变更 | 仅改变后续生成行为，不触发任何生成 |
| 浏览… | 点击 | 目录选择对话框；取消不改变输入框 |
| 保存参数 | 点击 | 写 JSON；jsonschema 校验失败时**逐字段**标红并在状态栏汇总，不弹窗 |
| 加载参数 | 点击 | 当前有未保存修改时先确认 |
| 任意字段变更 | — | 状态栏进入「参数已修改」态；已有下游产物时追加一致性警告 |

### 4.1 参数与已有产物冲突

改动 题材 / 子题材 / 篇幅 / 结构 / 主题 时，若下游阶段已有产物，
状态栏显示 warn 提示；**不自动删除任何产物**，也不自动重置阶段状态。

## 5. 阶段 5 · 章节撰写

| 控件 | 触发 | 结果 |
|---|---|---|
| 撰写下一章 | 点击 | 主按钮进入 busy；右栏当前章行变 accent.tint + 转圈；状态栏接管进度与停止 |
| 撰写全部剩余章节 | 点击 | 同上，进度粒度为 `第 N 章 · 场景 i/j`；每章完成即落盘 |
| 重写本章 | 点击 | 目标章已有内容时先确认；重写期间正文区显示旧稿（ink.400），新内容追加在下方 |
| 分析章节 | 点击 | 只读操作，不进 busy 态；结果写入右栏 |
| 章节列表行 | 点击 | 切换正文区；生成中不阻止切换，但状态栏仍指向生成中的那一章 |
| 停止 | 点击 | 见 1.2；已落盘的场景保留，未完成的章标为 `PARTIAL` |

生成中正文区：已定稿段落 ink.900；流式生成的最后一段 ink.600 + 行尾 2px accent 光标；
不自动滚动到底（用户上滚时锁定；回到底部后恢复跟随）。

正文区排版：`Source Serif 4` 16px / 行高 1.95 / 左右内边距 64px / 首行缩进 2em。

## 6. 阶段 2 · 世界设定

左侧是产物浏览器而非表单：这一阶段用户的实际任务是读结果、决定要不要重跑。

| 控件 | 触发 | 结果 |
|---|---|---|
| 产物页签（世界观/势力/人物/地点） | 点击 | 切换左侧内容，不触发任何生成 |
| 势力/人物/星系 数量步进器 | 变更 | 上限 10；仅影响下次生成 |
| 生成势力 / 生成人物 / 生成世界观 | 点击 | 单步 busy 态；已有产物时先确认覆盖 |
| 完善主要人物 | 点击 | 需人物已生成，否则按钮为 locked 态 |
| 重新生成世界观 | 点击 | 二次确认；不删除势力与人物产物 |

分步按钮自带完成标记与产出数量（`✓ 生成势力  6 个`），按钮即状态显示，
不再另设一行文字说明。

题材附加参数（星系数量等）随子题材变化，标签文案沿用 `update_extra_parameter`
的映射（势力/机构/社会团体/教团）。

## 7. 阶段 3 · 故事结构

| 控件 | 触发 | 结果 |
|---|---|---|
| 幕卡片 | 点击 | 展开该幕全文；未通过的幕默认展示评审意见原文 |
| 生成人物弧光 / 势力弧光 / 融入地点 | 点击 | 单步 busy；互不阻塞，可乱序执行 |
| 重跑未通过的 N 幕 | 点击 | 只重跑 `rejected` 的幕，已通过的幕不动 |
| 查看评审记录 | 点击 | 打开评审历史（每轮意见 + 差异） |

主按钮文案随状态变化，界面只呈现当前唯一有意义的动作：

| 阶段状态 | 主按钮文案 |
|---|---|
| 未生成 | `生成故事结构` |
| 有 rejected 幕 | `重跑未通过的 N 幕` |
| 全部通过 | `创建详细情节` |
| 重试轮次耗尽 | `重跑未通过的 N 幕`（次要样式）+ 状态栏提示已达上限 |

「门禁」面板常驻右栏，逐条列出下一阶段被阻塞的原因，并说明重跑后自动解锁。

## 8. 阶段 4 · 场景规划

被阻塞时不显示表单，显示阻塞空态：

- 标题回答「为什么空」：`需先完成「故事结构」`
- 正文逐条列出具体缺口（第 N 幕 + 评审结论摘要）
- 主动作 `前往故事结构`（跳转并聚焦第一个 rejected 幕）
- 逃生口 `忽略门禁，强制规划`（次要样式 + 一行后果说明）

强制规划的行为约定：不删除任何已有产物，生成的场景不标记为已通过，
阶段状态保持 `PARTIAL`。

「输入依赖」面板显示门禁读的是磁盘产物而非运行记录——用户手改文件后，
需点侧栏刷新重新评估。
