# UI 交互契约（PySide6 重构）

设计画布定义"长什么样"，本文件定义"怎么动"。写 PySide6 时以本文件为规格；
两者冲突时以本文件为准，并回头修画布。

状态枚举沿用 `core/generation/workflow_status.py` 的 `BLOCKED / PARTIAL / COMPLETE`。

## 0. 设计 token

| token | 值 | 用途 |
|---|---|---|
| `ink.900` | `#1C1B19` | 主文字 |
| `ink.600` | `#6E6C67` | 次要文字、标签 |
| `ink.400` | `#9A9792` | 三级文字、禁用 |
| `line` | `#E4E4E1` | 分隔线、卡片边框 |
| `line.strong` | `#D6D5D1` | 次要按钮边框 |
| `rail` | `#F4F3F0` | 左侧栏底色 |
| `canvas` | `#FFFFFF` | 卡片/编辑区底色 |
| `surface` | `#FAFAF8` | 内容区底色、状态栏 |
| `accent` | `#2C4A7C` | 主按钮、当前步骤、生成中 |
| `accent.tint` | `#EDF1F8` | 聚焦光晕、选中行 |
| `success / warn / danger` | `#2F7D4F` / `#B4761D` / `#B3392F` | 语义 |

间距只用 4 的倍数；字号只用 11 / 12 / 13 / 16 / 19；控件高 32px；圆角 4px（卡片 6px）。
字体：界面 `Noto Sans SC`（回退 `PingFang SC` / `Microsoft YaHei`）；
标题与正文稿 `Source Serif 4`（回退 `Songti SC` / Georgia）。

强调色只允许出现在：主按钮、当前步骤指示条、生成中徽标与进度条。一屏不超过 3 处。

### 1.2 底部状态栏

单一后台任务通道。同一时刻只显示一个任务。

| 状态 | 内容 |
|---|---|
| 空闲 | 灰点 + `空闲`｜输出目录｜右侧 `上次保存 HH:MM` |
| 运行中 | 转圈 + `正在<动作> · <子进度>` + 进度条(200×5) + 已用时 + 右侧红色 `停止` |
| 参数脏 | warn 半环 + `参数已修改，尚未保存` + 一致性提示 |
| 失败 | danger + 错误摘要 + `查看日志` 链接（点击打开日志文件） |

`停止` 只在任务运行时出现，绑定 `CancelToken.cancel()`；点击后立即变为
`正在停止…` 并禁用，直到 worker 抛 `GenerationCancelled`。

## 2. 后台任务契约（替换 task_runner.py）

Tk 的 `root.after` 轮询改为 `QThread` + 信号。调用方约定不变：

| 旧参数 | 新形态 |
|---|---|
| `busy_widgets` | `TaskRunner.run(..., disable=[w1, w2])` |
| `busy_button` + `busy_text` | 按钮进入 `busy` 态：自身禁用、文案换为 `busy_text`、左侧加转圈图标 |
| `cancel_button` | 不再由调用方传入；统一由状态栏的 `停止` 承担 |
| `on_success / on_error / on_done` | 信号 `succeeded(object)` / `failed(Exception)` / `finished()`，均在主线程 |
| `on_cancelled` | 信号 `cancelled()` |

worker 线程**禁止**触碰任何 QWidget。进度上报走 `progress(str, float)` 信号。

### 5.1 未通过质量闸门的章节

闸门拦下一章时，问题必须**第一步**就摆在作者面前。不允许只报一句
「请人工审核」再让作者自己去归档目录和评审目录之间对时间戳。

生成侧在 `quality/pending_review/chapter_<N>.json` 留一份记录：这一稿正文、按严重
程度排好的问题清单、以及重修与放行要用的现场。章节被验收后该文件即删除，所以
文件存在本身就等于「这一章待复审」。

| 位置 | 表现 |
|---|---|
| 章节列表 | 单列一档 `待复审`：warn 半环 + 右侧 `N 处硬伤` / `N 项未达标`，与 `待撰写` 一眼分得开 |
| 页头副标题 | `第 N 章待复审 · 已完成 M 章 · X 字` |
| 选中行为 | 刚出现的待复审章自动选中；已经知道的不抢当前选中 |
| 正文区 | 显示被拦下的那一稿，顶部 warn 横幅注明不在正式稿件里；被点名的句子标底色（硬伤 `#F6DCD9`，建议 `#FBF1DF`） |
| 右栏「复审」卡 | 卡在哪个评审、差多少分；评审给的位置；问题清单按 硬伤 → 未达标维度 → 可选润色 排序，点一条滚到正文对应位置 |

清单里带勾选框的条目才会进重修提示词；分数维度没有可执行文本，不给勾选框。

| 控件 | 触发 | 结果 |
|---|---|---|
| 照建议重修 | 点击 | 只带勾选中的条目跑一轮定向重修；全部划掉时拒绝执行并说明原因；重修仍不过则刷新清单，章节留在待复审 |

勾选中的条目先按各自引用的原文分派到所在场次，哪几场有条目就改哪几场，每一场只
收到属于它自己的那几条。评审给的位置只写一个场号，但它开出的条目常常散落在整章；
照那一个场号改，其余条目就是发给模型却没有对应正文的要求。找不到出处的条目归给
评审指名的那一场。

代价：每多一场要改，一轮就多两次模型调用（改写一次、复评一次）。

#### 出在规划里的问题不发给重修

有些硬伤重写多少遍正文都不会好，因为根子在场景规划：规划写着
`「梁浩在'海陵先驱号'上只有不到四十分钟」`，而上一章结尾的倒计时是十四分二十秒，
读者盲测每一轮都报时序矛盾；另一章的规划写死了一句台词 `「是顾阳波质谱分析报告
里的…」`，现实合理性每一轮都报精度无据。**照规划写就过不了评审，不照规划写就违反
契约**，重修被夹在中间，白耗一轮章节级重修（约十次调用）。

判据是确定性的，不花调用：每条硬伤都必须附一段正文里逐字可检索的引文（本项目一贯
的约束），把那段引文拿去和场景规划比，共用片段达到 12 个汉字就算「正文只是照规划
写的」。门槛按实测定——真出在规划里的三条命中 13、19、20 字，正文自己的问题全在
7 字以下，两边各留五个字余量。宁可漏判：漏判只是退回原来的行为，误判会把真该改
正文的地方放过去。

| 位置 | 表现 |
|---|---|
| 重修清单 | **先给一轮机会**；同一条挺过自己的修复之后才撤下，其余条目照常分派到各场 |
| 复审卡 | 条目始终留在清单里，作者看得到；旁边写明规划第几场的哪一句要改 |
| 账本评审记录 | 警告里写着 `「以下问题出在场景规划本身，重写正文改不掉」`，逐条附上规划原句 |
| 照建议重修 | 勾选的条目全部是规划缺陷时**拒绝执行**并说明该去哪儿改，不拿空清单去改正文 |

「先给一轮机会」是实测换来的：第一版一检测到就全撤，结果重修手上什么都不剩，同样
的问题原样留到最后，第 23 章反而掉进了待复审——比不撤更糟。**引文照搬了规划不等于
正文没救**：规划那句话往某个方向推，正文往往仍有回旋余地（`「在船上」` 改成
`「正在登船」` 就能解掉空间矛盾）。只有同一条挺过了它自己的修复，才算证明正文改不
动，这和循环里既有的「同一个错误挺过自己的修复就收手」是同一条原则。

抓不到语义层面的规划缺陷：规划要求「以公诉代理人身份向法警下达羁押指令」，正文换
一套说法写出来，字面对不上。那种仍旧当成正文问题走重修，最终由作者判断。

#### 一场只能写到下一场开始之前

写第 N 场时，提示词里的内容按三个名义分开摆：

| 内容 | 放在哪 | 名义 |
|---|---|---|
| 本场及此前的契约记录 | 契约块 | 必须兑现 |
| **本章后面场次的边界** | 单独一段 | **一个字都不许碰** |
| 下一场的规划 | 只给标题行 | 只用来定收束位置 |

定向重修改写某一场时照办同一套。**闸门用的仍是完整契约**，分栏的只是提示词副本，
没有放宽任何检查。

这一版是四轮实测换来的，中间走错过一次，记在这里免得再走：

1. 原先下一场的规划整段发过去（5000 字，含环境、出场人物、编号的关键事件表），
   同时在提示词里请它「不要提前完成下一场的任务」。**实测它会用**：重修之后的
   场次被判 `NEXT_SCENE_PREMATURE`，代价是多跑一轮章节级重修（约十次调用）。
2. 改成只给下一场的标题行。越界没有消失，只是从第 24 章挪到了第 23 章——因为
   材料还有第二份：章节契约里的场次边界那一栏一句话就把后面几场写明白了
   （`「scene_3: …（郑伟川被捕瘫倒，法官当庭裁决梁浩无罪）」`），而那一份的抬头
   写着「必须兑现」。
3. 于是把后面场次的边界一并从契约副本里删掉。**这一步是错的，而且代价明确**：
   第 23 章一章内越界 2 次，三轮定向重修分数一路从 3.14 掉到 1.96，最后进了待复审。
   评审的判词说破了原因——第一场「提前消耗了 scene_2 和 scene_3 的全部核心冲突，
   导致后续两个场景无戏可写」。那几行同时还在**当栅栏**用：模型靠它们才知道自己
   这一场到哪儿为止，删掉之后不是变谨慎，是失去参照，一路写到底。
4. 最终版：信息一个字不减，只换名义。后面场次从「必须兑现」的清单里移到「一个字
   都不许碰」的清单里。

带场次标记的记录（事实在哪一场首次出现、线索在哪一场埋下、叙事状态在哪一场转换）
仍按场次过滤——那些是要交付的材料，不是栅栏。按**埋下**的场次过滤而不是按兑现的
场次，否则第一场就看不到自己要埋的那条线索；看不出属于第几场的一律保留，那有可能
正是本场必须遵守的约束。

边界这件事分成三段，各归各的：**代码决定发什么给模型**（上面两条）、**评审判写出来
的算不算数**、**代码决定判完之后怎么处置**（按引文路由到具体那一场、定向重修、重修
完重判）。生成式的一步没有办法禁止模型写出某段文字，能管的只有前后两头。

判定这一段试过改成确定性统计，**做不到**，试算记录在案：把当初被判越界的那一稿从
调用轨迹里取回来，对照本场与下一场规划算三种判据——与下一场规划逐字共用的片段、
下一场专属的 2–3 字词、再加一层「全书前面章节从未出现过」的过滤——没有一种能把
越界那一稿和改好那一稿分开，逐字片段那一条还反过来在干净的场次上误报。原因是越界
的稿子不抄规划的字：规划写 `「当庭敲响法槌」`，正文写 `「法官在审判台上重重敲下法槌」`，
一个字都不重合。**它抄的是事件，不是措辞。**

跨章套语那条能用统计判，是因为那里的缺陷本身就是逐字重复；场次越界的缺陷是「同一件
事被提前写了」，措辞可以完全不同，所以只能留给读得懂正文的那一份评审。硬凑一个噪声
很大的统计去顶替它，会拦下干净稿子又放过真越界的，比现在更糟。

场景评审那一份照旧拿到下一场的完整规划——它要判的正是「有没有越过边界」，把参照物
从它手上拿走就没法判了。

#### 同一场的多轮重修走对话

改同一场时，模型看得见自己上一稿：第一轮把当初的写作依据作为开场要求、把手上这
一稿作为它自己的回答放进对话，之后每轮只发新的修改清单——契约、场景规划、上一场
结尾在第一轮里说过了，不必每轮重念。第二轮改同一场时，它第一轮改了什么、当时被
要求了什么都还在。

一次性提问里上一稿是「一段别人给的文字」，模型倾向整体重写；作为对话是它自己的
回答，改动更贴着被点名的那几句走。

- 每一场一段对话，不串场；正文被别处改过就重新起头，避免改到一份已经作废的稿子上
- 只有自建的 OpenAI 兼容端点走真正的多轮，其余后端摊平成一次提问，行为与原来一致
- 作品参数写 `Scene Dialogue: off` 关掉，退回一次性提问那条路。参数不写就是开启

注意这不省 token：每一轮仍旧把整段对话作为输入重发一次。它要换的是命中率，不是
账单。

**实测（2026-09-06，第 23–25 章各跑一遍，同一副本、同一批契约）**：开与关都是三章
全部验收、零放行、零待复审；章节级重修开是 1/2/1 轮、关是 1/1/1 轮；调用次数开 91 次、
关 73 次（+25%）；相邻章开头共用套语开 2 条 / 关 1 条，承接锚点开 13 处 / 关 18 处。
也就是说，这一次没有量到它提高命中率，代价倒是量到了。三章一遍的样本定不了结论
（同一章在不同次跑里结果本来就会变），但目前没有支持「默认开着」的数据，要么再攒
样本，要么把默认改成关。

| 人工放行 | 点击 | 先问放行理由；放行只改评分判定，**验收照跑**，理由写进账本评审记录 |
| 回去改规划 | 点击 | 跳到场景规划阶段 |

一稿只写到一半就被拦下（场景级闸门）时没有完整章节：`照建议重修` 与 `人工放行`
均禁用并说明原因，出路是 `重写本章`。

#### 评审自己没能出结论

大模型的评审回复没写完、或形状不对（补救一次后仍旧如此）时，这一章同样进待复审，
不再一路抛成报错把整遍成果丢掉——判不合格与判不出来对作者是同一个后果（这一章
进不了正式稿），正文就该同样留住。章节级检查前后失灵时现场是完整的；场景还没写
完就失灵的，交出的只有半稿，与场景级抬手一样不可放行。

| 位置 | 表现 |
|---|---|
| 章节列表 | 右侧写 `评审未出结论`（没有问题清单可数） |
| 正文区横幅 | `质量评审没能给出结论，这一稿暂不进正式稿件` |
| 复审卡 | 无问题清单；`照建议重修` 改名为 `重跑评审`；`人工放行` 照常可用 |

`重跑评审` 只重判、不改一个字：通过就直接收进正式稿件，不通过再按新清单走定向
重修那条路。`人工放行` 等于作者替评审签字，这件事写进账本评审记录（`质量评审未能
给出结论`），事后查得出这一章根本没被判定过。

大模型的原始回复存进本章的评审目录（`review_unavailable_*.json`）。只记一句错误
摘要是查不出原因的：漏字段、形状写错、根本没写完，处置完全不同。

走到这一步之前还有几道拦截，都在评审内部完成，作者看不到：

- 回复为空时原样重问（最多 3 次）。托管端点会在同一个提示词上时而返回正文、时而
  只返回空，而且每次都报「正常结束」、都计了几百到几千 token 的生成量。空回复不是
  模型的回答，是这次调用没成。
- 回复写到一半断掉时同样原样重问（最多 3 次），而不是让模型去「修」一份它根本没
  写完的东西——那会白白吃掉评审仅有的那次补救机会。
- 章节级三份评审（契约、读者盲测、现实合理性）里有一份始终问不出结果时，用在场的
  两份判定，并把缺的那份写进警告与账本记录。少一个意见不该盖过在场的两个；三份里
  两份都问不出来才是真的判不了，那时仍旧交给人工。

- 回复读不出来时，绝不从坏掉的那一块里捡里面的小对象顶包。捡到的往往正是评分表
  自己，于是报出来的错变成「评审里没有评分表」——模型明明写了评分表，照这句话
  去改根本改不到点子上。
- 补救那一次连 JSON 都写坏时，退回第一次那份读得出来的判定（第一次若只是低分维度
  缺少对应改法，补救一轮之后本就不再有阻断资格）。一个引号写错不该毁掉整章。

批量写作遇到一章被拦下**仍然整轮停下**——章节有顺序依赖，上一章未验收就往下写
只会把错误扩散到后文。要改的是停下来时给什么，不是停不停。

正文区排版：`Source Serif 4` 16px / 行高 1.95 / 左右内边距 64px / 首行缩进 2em。

## 6. 阶段 2 · 世界设定

左侧是产物浏览器而非表单：这一阶段用户的实际任务是读结果、决定要不要重跑。

| 控件 | 触发 | 结果 |
|---|---|---|
| 产物页签（世界观/势力/人物/地点） | 点击 | 切换左侧内容，不触发任何生成 |
| 势力/人物/星系 数量步进器 | 变更 | 上限 10；仅影响下次生成 |
| 生成势力 / 生成人物 / 生成世界观 | 点击 | 单步 busy 态；已有产物时先确认覆盖 |
| 完善主要人物 | 点击 | 需人物已生成，否则按钮为 locked 态 |
| 重新生成世界观 | 点击 | 二次确认；不删除势力与人物产物 |

分步按钮自带完成标记与产出数量（`✓ 生成势力  6 个`），按钮即状态显示，
不再另设一行文字说明。

题材附加参数（星系数量等）随子题材变化，标签文案沿用 `update_extra_parameter`
的映射（势力/机构/社会团体/教团）。

## 8. 阶段 4 · 场景规划

被阻塞时不显示表单，显示阻塞空态：

- 标题回答「为什么空」：`需先完成「故事结构」`
- 正文逐条列出具体缺口（第 N 幕 + 评审结论摘要）
- 主动作 `前往故事结构`（跳转并聚焦第一个 rejected 幕）
- 逃生口 `忽略门禁，强制规划`（次要样式 + 一行后果说明）

强制规划的行为约定：不删除任何已有产物，生成的场景不标记为已通过，
阶段状态保持 `PARTIAL`。

「输入依赖」面板显示门禁读的是磁盘产物而非运行记录——用户手改文件后，
需点侧栏刷新重新评估。

### 8.1 章节衔接必须在规划阶段就说清楚

连载读者是接着上一章往下读的。之前每一章都从零开始锚定时间、描写地点、介绍在场
人物，读起来像每章重新开书——第 18、19、20 章连着三次把同一个防空洞从头铺了一遍。
根子在规划：契约里根本没有一个字段负责回答「这一章从上一章的什么状态接过来」。

第二章起，章节契约必须填 `continuity`，三项都不能空、也不能写「无」「待定」：

| 字段 | 内容 | 判为不合格的情形 |
|---|---|---|
| `picks_up_from` | 本章开场直接承接上一章结尾的哪一个动作或悬念 | 留空、占位词、少于 8 个汉字，或只写一句「承接上一章」 |
| `time_gap` | 与上一章结尾之间隔了多久 | 留空或占位词 |
| `opening_positions` | 开场时谁在哪，至少一条 | 空数组，或任一条缺人物名 / 缺地点 |

`chapter_function` 同时从「可留空」改为必填，取值限
`advance｜reveal｜relationship｜aftermath｜transition｜breather`。

不合格的契约走**已有的规划重试**：错误连同上一稿一起发回模型，重试次数与其它契约
缺陷共用同一个预算。规划阶段还会把这些送进提示词，全部来自已落盘的产物，不额外
花调用：上一章结尾原文、上一章最后一个记账事件的时刻与地点、最近三章已经建立过的
地点与人物名单、以及已经连续几章没被碰过的悬念。

已验收章节的规划不再重新生成——它对应的正文已经落盘，重规划只会让两者对不上。
旧项目里还没有衔接字段的契约，走**定点补写**：只问那三个字段（一次调用），场景
规划的 Markdown 一个字不动。

### 8.2 规划阶段新增的确定性跨章检查

都不花模型调用。前两条判定为阻断，走规划重试；后两条只作提示，写进本章的
`continuity` 评审记录。

| 检查 | 判据 | 处置 |
|---|---|---|
| 章节功能重复 | 本章与紧邻的前两章 `chapter_function` 完全相同 | 阻断 |
| 时间读数倒流 | 本章第一个事件与上一章最后一个事件**日标签相同**，而时刻更早 | 阻断 |
| 日标签回退 | 本章的日标签上次出现在更早的章 | 提示 |
| 日标签漂移 | 本章引入了新的日标签 | 提示（请作者确认与 `time_gap` 说的是同一段时间） |
| 悬念长期沉默 | 一条已埋下未了结的悬念连续 3 章以上没出现在任何 `plot_thread_updates` 里 | 提示，并列进下一章的规划提示词 |

日标签是自由文本，跨标签本来就排不出先后，所以只有「同一个标签下时间倒流」能下
确定结论。把排不出来的也判成错误，只会让作者去伺候一个猜的规则。

### 8.3 第一场的写作硬要求

第一场（且只有第一场）的提示词里多一段硬性衔接要求。第二场往后接的是上一场，不是
上一章，同样的要求发过去只会让模型在半途又写一次开场。

- 必须承接 `picks_up_from` 说的那件事，开篇前三段之内让读者认出来
- 时间差要可感，但不要用一段旁白重报一遍时刻表
- 开场站位照 `opening_positions` 写，不得改动
- **禁止**从零重新描写最近几章已经建立过的地点（渗水、灯光、管线、气味这类铺陈）
- **禁止**重新交代读者已经认识的人物的身份、职务、来历
- 禁止用「与此同时」「另一边」这类空转过场重新铺场

### 8.4 验收阶段的衔接判定

章节级闸门原本是三份评审合议（契约、读者盲测、现实合理性），现在多一份 **衔接**。
它是算出来的，不占调用，但和三份评审一起合议——它拦下的东西同样走定向重修。

读者盲测新增维度 `chapter_continuity`（第一章没有上一章可接，这一维度整条忽略），
拿得到上一章结尾，被要求先回答「这一章的开头是不是接着上一章」。两个新硬失败代码
沿用既有约束：**必须附正文逐字可检索的引文**，引不出原文的批评一律丢弃。

| 代码 | 什么时候报 | 谁判 |
|---|---|---|
| `CONTINUITY_BREAK` | 在上一章结尾里指不出本章开头承接的那件事 | 读者盲测 |
| `REDUNDANT_RESTAGING` | 重新铺陈上一章刚建立的地点，或重新介绍已认识的人物 | 读者盲测 |
| `OPENING_BOILERPLATE_REUSE` | 本章开头与上一章开头逐字共用的片段多于 2 处，或单条达到 20 字 | 确定性 |
| `OPENING_POSITION_UNMET` | 契约声明开场在场的人，正文开头 1500 字里没出现 | 确定性 |

套语比对只看两章开头各 1500 字，片段最短 5 个汉字；人物名与地点名先从片段里抠掉，
剩下不足 3 个字的当作纯专名丢弃——两章都写到「白鹤山看守所」不是套语，是同一个
地方。门槛按已验收章节实测定：相邻章之间最长的共用片段是 11 个字，每对 1–8 条。

还有一个方向相反的数字：**承接锚点**——本章开头 800 字与上一章**结尾** 2500 字之间
共用的片段（最短 4 个汉字）。和上一章开头重合是重新布景，和上一章结尾重合才是承接。
锚点为 0 时报一条提示：同一件事完全换一套说法说也可以接上，所以它不拦章；判「读起来
接不接得上」的仍是读者盲测。两个数字要一起读——第 18、19 章同时是套语 8 条、锚点
12 处，那是把上一章的结尾和开头一起重演了一遍。

本章的量化结果单独存一份 `continuity_*.json`（套语条数与字数、开场站位兑现情况、
时间读数与悬念沉默提示），合议之后的评审只留得下硬失败，数字没有别的地方可看。

### 8.5 成章验证

`tools/run_sandbox_chapters.py` 把 `current_work` 复制到 `sandbox_run/`，在副本上
连写指定的几章，输出每章是否一次过、各级重修轮数、有无放行或待复审、调用次数，以及
相邻章开头的共用套语条数。定稿的正文与账本一个字不动。

无人值守跑要加 `--approve-contradictions`：契约声明的事实反转按设计必须由人裁定，
副本里没有人坐在界面前。它把裁定显式记进账本，而不是把闸门放宽。
